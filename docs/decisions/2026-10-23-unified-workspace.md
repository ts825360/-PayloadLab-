# 통합 학습 공간 개선 — 승인 범위와 검증 기록

## 승인과 기준

- 사용자 요청으로 팀 저장소 `ts825360/-PayloadLab-`의 `main`을 기준으로 작업한다. 시작 커밋은 `232ae67`이다.
- AI 작업용 새 브랜치를 만들지 않고 main에서 검증된 변경을 커밋한다. 팀원 개인 브랜치는 보존한다.
- SQL Injection·Reflected XSS·IDOR·SSRF·Command Injection·Linux의 Easy/Normal을 유지한다. 권한상승 기초만 Easy 제공, Normal은 구현 예정이다.
- 공개 배포, 임의 셸·외부 요청 실행, 공격 데이터셋 자동 실행, 새 이슈 등록은 하지 않는다.

## 작업 구분

1. **현황/기존 작업 확인**: 등록된 13개 랩, 분석/실행 구분, 단계형 안내, 키보드 동작의 회귀 테스트를 실행한다.
2. **UX**: `App`은 기존 상태와 API를 유지하며 `통합 학습 작업 공간`을 렌더링한다. `InputDock`은 유형별 로그인·검색·주문·URL·진단·터미널 문맥을 제공한다. `ObservationStage`는 같은 도구 내부의 처리/결과 영역으로 재사용한다. `GuidedLesson`은 재구현하지 않는다.
3. **입력 전 학습**: 별도 순수 학습 메타데이터에 정의·성립 조건·목표·처리 단계·다음 행동을 둔다. Easy는 안내, Normal은 목표와 선택형 힌트다. 빈 입력에서도 교육용 개념도와 진행 안내가 보인다.
4. **디자인**: 기존 Light/Dark 변수를 기반으로 semantic token을 추가한다. 코드·상태·입력·표·터미널의 하드코딩된 색을 토큰으로 대체/상쇄한다. 로고 원본이 없으면 기존 문자 브랜드를 유지하고 필요한 원본 에셋을 보고한다. 새 심볼을 임의로 확정하지 않는다.
5. **문서/구조**: 실제 파일·Compose·테스트 명령을 기준으로 README와 구조 문서를 작성한다. 별도 구현 저장소 안내를 현재 단일 저장소 안내로 수정한다. 캐시·빌드 산출물은 추적/배포에서 제외하되 원본 소스·역사·manifest는 보존한다. 사용하지 않는 구형 UI는 참조 조사를 기록한 후 이동 여부를 제안하고 이번에 대규모 리네이밍하지 않는다.
6. **배포 준비**: 실제 상태 저장 방식별 TTL 필요성을 구분한다. 보안 검증 제안은 기존 #6·#12·#24에 연결한 로컬 이슈 초안으로 작성하고 승인 없이 새 이슈를 등록하지 않는다.

## 테스트와 위험

- 먼저 통합 공간·유형별 인터페이스·빈 입력 13개 조합의 실패 테스트를 추가한다.
- 기존 API/조건 판정/출처 계약을 바꾸지 않는다. 레이아웃 의미가 바뀐 기존 테스트는 새 사용자 동작으로 갱신하되 Enter·Shift+Enter·Esc 확인·비교·IME·오래된 응답 차단 검증을 유지한다.
- 새 화면은 DOM 테스트/빌드와 브라우저 화면 검증을 분리해 기록한다. 외부 접근 제한 등 배포 안전성은 테스트 통과만으로 완료 처리하지 않는다.
- 로컬에서 구형 저장소를 실행 중이면 프로세스 경로를 확인해 이 main의 서버로 교체한다. 다른 프로젝트 프로세스는 종료하지 않는다.

## 완료 근거

### 2026-10-24 검증 결과

- 백엔드 전체 `pytest backend/tests -q`: **100 passed**.
- 프론트엔드 전체 Vitest: **11개 파일, 52개 테스트 통과**. 13개 지원 조합의 초기 학습 내용, 입력 전/후 전환, Easy/Normal, Enter·Shift+Enter·IME, Esc 확인, 비교·과거 응답 차단을 포함한다.
- Vite 프로덕션 빌드 및 `docker compose config --quiet`: 종료 코드 0.
- 데이터셋 원문·CSV·manifest 검사: **7개 통과**. 샌드박스 임시 폴더 권한 오류는 정상 권한으로 재실행해 구분했고, 데이터 원본은 수정하지 않았다.
- 브라우저 직접 확인: 1280×720 및 이전 좁은 화면에서 통합 작업 공간, SQL 일반 이름·조건 입력·Lens·결과, 라이트/다크 표시, 권한 Easy 접근 거부, 권한 Normal 구현 예정, SQL Normal 선택형 단서를 확인했다. 모든 운영체제·모바일 기기·접근성 조합의 인증을 뜻하지 않는다.
- 리뷰에서 발견한 라이트 확대 문장의 낮은 대비를 수정했다. 실제 선택자에 적용되는 글자색/배경을 검사하는 회귀 테스트를 추가했다. 최종 재검토에서 Critical/Important 지적은 남지 않았다.
- 권한 실습에서 지원하지 않는 명령 이후 정상 명령까지 막히는 기록 문제를 수정했다. 실패 시도는 화면에 보존하되 `unsupported` 결과는 가상 상태 재생에서 제외한다.
- 기존에 추적되던 Python 캐시 19개와 프론트 빌드 산출물 3개를 Git 추적에서 제외했다. 로컬 파일·원본 코드·Git 이력·데이터 출처는 보존한다.

### 남은 승인·외부 조건

- Docker CLI 설정 검사는 통과했지만 Docker Desktop Linux 엔진이 실행되지 않아 이미지 빌드·컨테이너 동작은 검증하지 않았다.
- 팀 로고 SVG/PNG 원본이 없어 브랜드 파일 통합은 보류했다. [필요한 원본](../branding/README.md)을 명시했다.
- [보안 점검 이슈 초안](../deployment/security-review-issue-draft.md)은 #6·#12·#24와 연결했으며, 새 이슈 등록과 공개 배포는 하지 않았다. XSS 원본 렌더·CSP·외부 요청·실제 격리는 공개 전에 별도 검증해야 한다.
