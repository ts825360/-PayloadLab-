## 열어 둘 항목

- #1·#2 필독, #4 색인: 계속 참고하는 허브다.
- #5: 유형별 조사/구현 담당 배정 항목이 아직 미완료다. 역할군 배정과 유형별 배정은 다르다.
- #6: 기존 ‘전부 모의·외부 URL 입력 금지’ 표현과 실제 SQLite/XSS 및 SSRF 문자열 입력의 경계를 맞춰야 한다. 법적 승인 완료를 주장하지 않는다.
- #8·#26·#28: 공통 envelope는 있지만 learning_trace의 자유 형식 dict와 유형별 확장 계약의 형식 검증이 남아 있다.
- #10·#31·#32: 기존 lens_steps 조건 체인과 현재 learning_trace 문안/단계 표시 정합성, 입력 수정 시 피드백 기준을 검토해야 한다. #19 문안 검토와 연결한다.
- #11·#13·#30·#37: 구현·일부 화면 근거는 있으나 세 유형의 대표 화면과 긴 입력·모든 반응형/접근성 점검을 일괄 완료로 처리하지 않는다. 새 로고의 육안 확인도 미실시다.
- #14–#19: 구현과 팀 조사·문안 검토 결과 제출을 구분한다. `docs/research/`에는 현재 README만 있으며 관련 결과 댓글도 확인되지 않은 항목은 대신 완료 처리하지 않는다.
- #12: 기동은 완료했으나 아웃바운드 제한·외부 PC 접근 실험·새 환경의 재현성은 남아 있다.
- #22: 기존 회귀 체계는 통과했지만 공개 전 공통 입력 크기·실행량·요청 제한의 추가 매트릭스가 필요하다.
- #24: [1차 보안 점검](../deployment/2026-10-24-public-readiness-review.md)에서 공개 차단 사유를 확인했다. 수정·재검증 전에는 닫지 않는다.
- #25: 최종 보고서·영상·가이드 검토가 남아 있다.
- #29: 일부 비정상 값은 learning_trace 없이 서버 확인 안내로 끝나는 경로가 있어 Lens 폴백 보장까지 완료되지 않았다.
- #34: DVWA 비교를 README·발표 자료에 정리하는 산출물 확인이 남아 있다.
- #35: IDOR의 도달 불가능한 guessable_id 규칙이 여전히 남아 있다.
- #36: 태그 인식과 실제 JS 실행의 구분은 있지만 최종 지원 형태·제외 형태의 교육 범위 확정이 남아 있다.

이슈 종료는 구현/설계의 명시된 범위를 충족했다는 뜻이며, 팀원의 실제 기여를 대신 작성하거나 공개 배포를 승인하는 절차가 아니다. 새 개선 의견은 닫힌 이슈에도 댓글로 남길 수 있다.
