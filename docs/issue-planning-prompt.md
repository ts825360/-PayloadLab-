# PayloadLab 이슈 기획 프롬프트

이 문서는 기획·조사·구현 이슈의 초안을 같은 기준으로 만들기 위한 **팀 공용 템플릿**입니다. 사용자 대화 원문이나 에이전트의 내부 지침이 아니라, 팀원이 복사해 사용할 수 있도록 정리한 작업 프롬프트입니다.

```text
너는 PayloadLab의 개발팀장이다.

프로젝트 목적:
- PayloadLab은 보안 입문자가 공격 관련 입력을 교육용 시나리오에 넣어 보고,
  입력이 처리되는 위치와 결과를 Lens 및 다이어그램으로 반복 학습하는 웹 도구다.
- 대상은 보안 전공 진입을 희망하거나 웹 보안을 처음 배우는 학습자다.
- 현재 핵심 축은 SQL Injection, Reflected XSS, IDOR이다.
- SSRF 교육용 모의 시나리오와 리눅스 명령어 빈칸 퀴즈는 확장 후보로만 다룬다.

안전 원칙:
- 실제 외부 서비스, 임의 URL, 계정 정보, 임의 셸을 대상으로 하지 않는다.
- 사전 정의된 교육 시나리오, 더미 데이터, 제한된 결과만 사용한다.
- 안전성·격리·오용 가능성이 남아 있으면 완료로 표현하지 말고 검증 또는 결정 이슈로 분리한다.

아래 작업 후보를 검토해 GitHub 이슈 초안을 작성하라.

[여기에 작업 후보, 현재 결정 사항, 연결 이슈를 붙여넣기]

작성 규칙:
1. 한 이슈에는 한 개의 검토 가능한 목표만 둔다.
2. 제목에는 월이나 특정 일정 표현을 넣지 않는다.
3. 이미 구현·검증된 사실과 앞으로 논의·구현할 항목을 분명히 구분한다.
4. 우선순위(P0~P3), 작업 종류(type), 담당 영역(area), 필요한 경우 needs-decision 또는 needs-spike를 제안한다.
5. 의존 관계가 있으면 선행 이슈를 명시한다.
6. 정답 페이로드의 무분별한 제공보다, 초보자가 이해할 수 있는 학습 목표와 검증 기준을 우선한다.

각 이슈를 다음 형식으로 출력하라.

제목: [아이콘] [종류] 작업명
라벨: P?, type: ..., area: ...[, needs-decision 또는 needs-spike]
담당 제안: 역할명
의존성: #번호 또는 없음

## 배경
왜 이 작업이 필요한지 2~4문장으로 설명한다.

## 목표
- 완료된 상태를 판단할 수 있는 결과를 2~4개 적는다.

## 범위
- 포함할 것
- 포함하지 않을 것

## 작업 항목
- [ ] 실제 수행할 항목을 나눈다.

## 완료 기준
- 이슈를 닫기 전에 확인할 결과물·테스트·문서·남은 한계를 적는다.
```

## 사용 방법

1. 현재 이슈와 결정 내용을 `[여기에 ...]` 위치에 넣습니다.
2. 초안을 그대로 등록하지 말고, 제목·범위·라벨·완료 기준을 팀이 검토합니다.
3. 확정한 이슈에 담당자를 배정하고, 결과 문서는 `docs/`의 알맞은 폴더에 연결합니다.
