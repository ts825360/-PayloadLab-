## 우리가 만들고 싶은 것

PayloadLab은 **보안을 처음 배우는 사람이 웹 보안 공격 원리를 직접 바꿔 보며 이해하는 연습장**입니다.

처음 배우는 사람은 보통 실습 환경을 설치하는 것부터 어렵고, 예시 문장을 넣어 성공해도 “왜 됐는지” 알기 어렵습니다. PayloadLab은 이 빈 부분을 채우려 합니다.

## 사용자가 보는 흐름

1. 배우고 싶은 유형을 고릅니다. 예: SQL Injection
2. 난이도를 고릅니다.
3. 입력칸에 문장을 넣습니다.
4. 성공했다면 입력이 코드나 쿼리에 어떻게 들어갔는지 그림으로 봅니다.
5. 실패했다면 Lens가 어디가 부족한지 알려 줍니다.
6. 사용자가 문장을 고쳐 다시 시도합니다.

## Lens는 무엇인가요?

Lens는 정답을 바로 주는 기능이 아닙니다. **사용자가 넣은 문장을 확대해서 설명해 주는 돋보기**입니다.

예를 들어 SQL Injection 입력이 실패하면 Lens는 다음 세 가지를 보여 주는 것을 목표로 합니다.

- 입력한 문장이 쿼리의 어느 위치에 들어갔는가
- 아직 빠진 조건이나 문법은 무엇인가
- 그 조건이나 문법이 왜 필요한가

사용자는 이 설명을 보고 다음 입력을 스스로 만들어 봅니다.

## 첫 버전에서 할 것

처음 버전의 중심은 아래 세 유형입니다.

| 유형 | 사용자가 배울 핵심 |
| --- | --- |
| SQL Injection | 입력이 쿼리 문장에 들어가면서 조건이 바뀌는 원리 |
| Reflected XSS | 입력이 브라우저에서 HTML로 해석되는 원리 |
| IDOR | 다른 사람의 자료를 볼 수 있게 되는 원인이 권한 확인 누락이라는 점 |

SSRF와 리눅스 명령어 퀴즈는 좋은 확장 아이디어이지만, 첫 세 유형의 학습 흐름과 설명 품질을 확인한 뒤 진행 여부를 다시 결정합니다.

## 하지 않을 것

- 실제 외부 웹사이트를 공격하게 하지 않습니다.
- 사용자가 임의의 URL, 계정, 명령어를 실행하게 하지 않습니다.
- 고급 해킹 도구를 만드는 것이 목표가 아닙니다.

정해진 교육용 화면과 더미 데이터 안에서만 입력 결과를 보여 줍니다. 공개 전에는 안전 점검을 별도로 합니다.

## 팀 작업 방법

1. 이슈 하나를 맡습니다.
2. 이슈 댓글에 “무엇을 확인할지”를 짧게 적습니다.
3. 조사나 결정 내용은 `docs/`에 문서로 남깁니다.
4. 구현이 필요하면 Pull Request를 만들고, 이슈와 문서를 연결합니다.
5. 결과와 남은 의문을 이슈에 남깁니다.
