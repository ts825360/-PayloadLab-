> Reflected XSS의 개념, 초보자 학습 범위, Lens 규칙 후보, 시나리오 근거를 정리합니다.
> **출처의 사실**과 **팀의 해석**을 별도 소제목으로 구분합니다.
> 실제 대상 시스템의 민감한 정보는 기록하지 않습니다. 예시는 모두 더미 값입니다.

## 요약

- 학습 목표: 입력값이 응답 HTML에 그대로 실리면서, 브라우저가 이를 글자가 아닌 HTML·스크립트로 해석하는 원리를 이해합니다.
- 범위: 기초(태그 해석·`<script>`·이벤트 속성)와 중급(속성값 탈출·단순 필터 우회) 2단계. 쿠키 탈취와 관리자 봇은 제외합니다.
- 방어 핵심: 출력 위치에 맞는 출력 이스케이프.

---

## 1. 출처의 사실

### 개념

- XSS는 공격자 입력이 웹 페이지에 삽입되어 브라우저에서 스크립트로 실행되는 클라이언트 사이드 취약점이다.
- 저장형(Stored), 반사형(Reflected), DOM 기반으로 나뉜다. 반사형은 요청에 담긴 입력이 저장되지 않고 바로 응답에 다시 출력되는 경우다.

### 방어 개념

- 기본 방어는 출력 위치(HTML 본문, 속성, JavaScript 등)에 맞는 출력 이스케이프다. 예: `<` → `&lt;`
- 보조 수단: 템플릿 엔진 자동 이스케이프, 쿠키 `HttpOnly` 설정, CSP(Content Security Policy).
- `<script>` 단어만 지우는 필터는 이벤트 속성(`onerror` 등)으로 우회될 수 있다.

### DreamHack 관련 문제

- 「웹 해킹 기초」 Path의 XSS Unit은 XSS 이해와 방어를 다루며, 실습 문제는 `xss-1`, `xss-2`다.
- 두 문제는 스크립트를 실행한 뒤 관리자 봇의 쿠키를 얻는 구조다.

## 2. 팀의 해석

### 초보자 학습 범위

| 단계 | 배울 것 | 예시 입력 (더미) | 난이도 |
| --- | --- | --- | --- |
| 1 | 입력이 HTML 태그로 해석됨 | `<b>hi</b>` | 기초 |
| 2 | 스크립트 태그 실행 | `<script>alert(1)</script>` | 기초 |
| 3 | 이벤트 속성으로 실행 | `<img src=x onerror=alert(1)>` | 기초 |
| 4 | 속성값 탈출, 단순 필터 우회 | `" onmouseover="alert(1)` | 중급 |

- 첫 버전은 원리가 가장 단순한 반사형만 다룹니다. Stored·DOM XSS는 반사형 위에 쌓이는 개념이라 다음 단계 후보로 둡니다.
- **제외:** 쿠키 탈취, 외부 서버로 데이터 전송, 관리자 봇. 실제 공격 도구에 가깝다고 판단했습니다.

### Lens 규칙 후보

| 규칙 ID | 감지 조건 | Lens가 보여 줄 설명 |
| --- | --- | --- |
| XSS-01 | 입력에 `<`가 없음 | 입력이 일반 글자로만 출력됩니다. 태그를 여는 문자가 필요합니다. |
| XSS-02 | 태그는 해석되나 실행 코드 없음 | 입력이 HTML로 해석된 부분을 강조하고, 실행 가능한 위치가 아직 없다고 알려 줍니다. |
| XSS-03 | `<script>`가 필터에 막힘 | 스크립트 태그 대신 이벤트 속성(`onerror` 등)으로도 실행될 수 있음을 설명합니다. |
| XSS-04 | 속성값 안에 갇힘 | 따옴표로 속성이 닫히는 위치를 표시합니다. |
| XSS-05 | 성공 | 브라우저가 실행 영역으로 바꾼 지점을 보여 주고, 이스케이프 버전에서 `&lt;`로 바뀌어 실행되지 않는 비교 화면을 띄웁니다. |

### 시나리오 근거

- **시나리오:** 더미 검색 페이지에서 `alert` 창 띄우기.
- **근거:** DreamHack `xss-1`과 `xss-2`도 "입력이 페이지에 그대로 실린다"는 반사형 구조에서 출발합니다.
- **차별점:** 쿠키 탈취 단계는 PayloadLab의 "하지 않을 것"과 충돌합니다. 그래서 실행 성공 여부만 판정합니다.
- **안전 메모:** 판정 방식은 두 가지 중에서 정해야 합니다. 실제 스크립트를 실행하지 않고 "실행되었을 위치"만 판정하는 방식, 또는 샌드박스 iframe 안에서만 실행하는 방식입니다. 성공 판정 기준은 #36, 실행 격리는 #43에서 확인합니다.
