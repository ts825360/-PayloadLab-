# 초보자용 Lens 문안 공통 템플릿·검토 기준

관련: [#19](https://github.com/ts825360/-PayloadLab-/issues/19), [#46](https://github.com/ts825360/-PayloadLab-/issues/46), [운영 가이드](../ISSUE-GUIDE.md).
작성일: 2026-10-27. 작성 대상: 이수웅(dtd2428), AI 보조.
상태: **기존 구현과 고정41사례에 대조한 공통 기준 초안. 본인·팀의 최종 검토는 대기.** 새 기능·인터프리터·실행 정책을 정의하는 문서가 아니다.

## 1. 목적과 적용 범위

설명은 ‘내 입력 → 서버가 만든 문장/요청 또는 모형이 읽은 조각 → 데이터·규칙과 비교 → 실제 결과 → 작은 다음 관찰’이 이어져야 한다.
사람이나 입력을 잘못된 공격으로 평가하지 않고, 이번 처리에서 확인한 사실과 아직 모르는 것을 말한다.

SQL/XSS/IDOR/SSRF/CMDi/Linux Easy·Normal과 권한 Easy에 같은 틀을 적용한다. 모든 유형을 공격 성공/실패로 이분하지 않는다. Linux는 퀴즈이며 권한·SSRF·CMDi는 가상 모형이다.
권한 Normal은 구현 예정으로 유지한다. CSV 출처·라벨 검토와 모든13개 실습의 실제 화면 최종 대조는 이 문서 작성만으로 완료되지 않는다.

## 2. 결과 설명 기본 틀

아래 다섯 역할을 자연스러운 문장으로 연결한다. 매번 동일한 문장을 기계적으로 반복하거나 모든 필드를 한 화면에 강제로 늘어놓지는 않는다.

> 내가 [입력칸]에 넣은 값은 [원문]이에요. [실제로 사용한 값]이 [조립 문장/요청/토큰의 위치]에 들어갔어요. [현재 행·사용자·대상 또는 이번 규칙]에서 [무엇과 무엇을 비교/처리했는지] 확인했어요. 그래서 [실제로 반환된 행·출력·차단/오류 안내 또는 미판정]가 표시됐어요. 다음에는 [현재 화면에서 가능한 관찰 한 가지]를 확인해보세요.

| 문안 역할 | 실제 근거 | 작성 기준 |
| --- | --- | --- |
| 내 입력 | raw_input, 입력칸 이름 | 입력을 특정한다. 빈 문자열은 빈 입력이라고 설명한다. 비밀번호를 새로 입력했다고 꾸미지 않는다 |
| 사용된 값·위치 | effective_input, composition, focus | 필터가 바꿨으면 원문과 사용값을 각각 말한다. 값이 안 바뀌면 변경을 지어내지 않는다 |
| 처리·비교 | condition_tree·선택 행, relations, network, command_model, quiz | 상대·대상·규칙을 명시한다. 지원하지 않는 구조를 해석한 것처럼 설명하지 않는다 |
| 결과 | 실행 후 execution, 실제 반환 행/표준 출력·오류 | 일반 입력·오류·차단·미지원·성공을 구분한다. 표준 출력이 없더라도 표준 오류 안내는 있을 수 있다 |
| 작은 다음 관찰 | 현재 버튼·행·입력 위치·출력 | 한 번에 하나의 관찰을 제안한다. 계정 표가 결과 창 안에 있으면 여는 버튼부터 안내한다 |

### 기존 Lens 필드에 연결하기

새 응답 형식이나 API 필드를 추가하는 제안이 아니다. 현재 코드는 다음 역할로 검토한다.

- title: 이번 현상을 짧게 식별한다. ‘틀렸어요’만으로 끝내지 않는다.
- what: 원문/사용값, 들어간 자리, 이번 처리와 실제 결과를 연결한다.
- why: 이번 데이터·규칙이 그 결과를 만든 이유와 모형의 한계를 쉬운 말로 설명한다.
- next: 지금 화면에서 실행 가능한 관찰 하나를 제시한다.
- focus: composition.value(실제 사용값) 안의 관련 구절을 가리키는 코드포인트 범위다. 조립 문장 전체인 composition.full의 인덱스와 혼동하지 않는다. 프론트는 UTF-16 범위로 변환하고 고정 접두어 길이를 더해 표시한다. 빠진 조각의 삽입 위치는 시작=끝일 수 있다.
- lesson: 필요한 유형의 개념을 연다. Linux 버튼에서 SQL 개념처럼 다른 유형으로 폴백하면 미통과다.

what 하나에 정보가 많으면 다음 문장으로 나누되, 원인과 결과가 끊어지지 않게 한다. 고정 글자 수 상한이나 단어 수를 이 문서로 새로 만들지는 않는다.

## 3. 실행 전·원문 오류·미판정

### 실행 전 분석

> 입력 [원문]이 [사용값/자리/조각]으로 읽혀요. 아직 [조회/가상 응답/퀴즈 채점]은 하지 않았어요. [직접 실행한 뒤 확인할 작은 관찰]을 해보세요.

분석의 execution=None이면 ‘두 계정이 반환됐다’, ‘가상 명령을 실행했다’, ‘퀴즈 정답으로 채점됐다’고 말하지 않는다.
SQL의 컴파일 검사에서 실제 문법 오류를 확인했다면 ‘조회 전 문법 검사에서 오류를 확인했다’고 설명할 수 있다. 계정 조회 결과를 확인했다는 말과 구분한다.
입력 편집 중 이전 시도 기록이 화면에 남는 경우, 그것을 새 입력의 실행 결과라고 설명하지 않는다.

### 오류 원문과 교육용 해설

DB가 반환한 오류와 모형이 만든 안내를 구분한다. 터미널 모형의 종료 코드1만으로 실제 OS·셸 오류라고 판단하지 않는다.
원문을 수정해 해설을 끼워 넣지 않고, 원문 옆 설명·Lens·흐름도는 같은 시도와 같은 원인을 가리키게 한다.
밑줄/짧은 설명 기능이 제공되는 상태에서는 그 범위와 설명을 함께 확인한다. 권한 Easy의 원문·밑줄·키보드 초점 설명·Lens·TUI 대조는 [권한 검토 기록](../verification/2026-10-27-permissions-lens-review.md)을 참조한다. 마우스 hover·터치·확대별 검증을 모두 수행한 것은 아니다.

### 해석하지 못한 입력

> 이번 결과는 [실제로 확인한 사실]이에요. 다만 [이 모형/해설 규칙]은 [해당 구조]를 해석하지 않아 원인 전체를 설명할 수는 없어요. [지원하는 작은 기본 구조]와 비교해보세요.

실제로 실행된 SQL이 성공했지만 조건 그림 규칙이 모르는 식이면 성공 사실은 보존하고 설명 범위만 제한한다. 실행 성공을 모형 미지원 실패로 바꾸지 않는다.
Linux에서 퀴즈 답과 토큰 순서가 다르다고 일반 Linux 문법도 틀렸다고 말하지 않는다.

## 4. 상태별 어조·판정 기준

| 상태 | 설명할 근거 | 피해야 할 말 |
| --- | --- | --- |
| 일반 값·정상 처리 | 이름 비교, 단일 호스트, 퀴즈의 정상 이름 목록 | ‘공격을 잘못 입력했어요’ |
| 조건 불충족·대상 없음 | 어떤 조건/행이 맞지 않는지, 조회할 대상 자체가 없는지 | 서로 다른 원인을 모두 ‘실패’로 묶기 |
| 실제 문법 오류 | 실제 SQLite 오류, 컴파일/조회 전후 구분 | 반환0행과 같다고 설명 |
| 정책 차단 | 이번 정책이 본 문자·값, 차단을 일으킨 위치 | 글자를 지우지 않았는데 ‘제거됐다’, 연결하지 않았는데 ‘연결 실패’ |
| 권한 거부 | 현재 가상 사용자·소유자·해당 권한 | ‘명령어 철자가 틀렸어요’ |
| 모형/해설 미지원 | 실제 결과와 해석 한계, 미평가된 부분 | 실제 Linux에도 없는 명령이라고 단정 |
| 태그 형태 인식 | 규칙이 인식한 형태 | 실제 JS 실행까지 확인했다고 단정 |
| 유형별 목표 달성 | 실제 반환/모의 출력/퀴즈 목표의 근거 | Linux 퀴즈 정답을 공격 성공이라고 표현 |

## 5. Easy와 Normal

| 항목 | Easy | Normal |
| --- | --- | --- |
| 시작 | 따라 할 예시와 관찰할 자리를 먼저 제시 | 변화한 조건과 목표를 먼저 제시 |
| 입력 예시 | 사용자가 직접 넣고 실행하는 예시 | 선택형 단서를 열 때 예시를 보여줌 |
| 설명 | 명령·옵션·값의 역할을 짧게 풀어줌 | 원문/사용값, 검사 기준, 다른 표기·조건의 영향을 비교 |
| 다음 행동 | 기본값 한 번 실행, 행 하나 선택 등 작은 단계 | 특정 결과를 만드는 조건을 관찰하도록 한 가지 단서 제공 |
| 단계 완료 | 실행 근거와 본인 관찰 확인 | 실행 근거와 본인 관찰 확인, 해당 단계에 질문이 있으면 답 확인 |

기존 getLesson과 GuidedLesson은 이 표와 같은 방향으로 동작한다. 예시 넣기는 입력만 채우며 자동 실행·자동 단계 완료로 취급하지 않는다.
위 내용은 코드 대조 결과이며 실제13개 조합의 빈 화면·단서 열기·다음 입력까지 모두 새로 대조했다는 뜻은 아니다.
권한 Normal을 새로 만들거나 다른 유형을 추가하지 않는다.

## 6. 적용 예시와 근거

아래 문장은 작성법 예시다. 실제 출력값·선택 행은 반드시 현재 trace로 채운다. 범용 해석 규칙으로 복사하지 않는다.

| 유형·사례 | 기준을 적용한 예시 | 근거·검토 한계 |
| --- | --- | --- |
| SQL / SQL-01 | 박태성을 이름 값으로 넣었어요. 선택한 계정 admin과 이름이 다르고, 고정 비밀번호도 맞지 않아 AND 전체가 거짓이에요. 실제로 이 행은 반환되지 않았어요. 결과 창에서 guest로 바꿔 이름 비교를 확인해보세요 | 선택 행 설명과 실제 반환을 함께 대조. 지원 조건식 범위만 설명 |
| SQL Normal / SQL-05 | 내가 쓴 원문과 서버가 사용한 값이 달라요. 이번에는 대문자 OR가 제거되어 연결 부분이 달라졌고 SQLite 문법 오류가 났어요. 두 값에서 바뀐 연결 위치를 비교해보세요 | 모든 필터 변경이 오류를 낸다고 일반화하지 않음 |
| XSS / XSS-04 | 검색어가 p 본문에 들어갔고 규칙은 script 태그 형태를 인식했어요. 실제 브라우저 실행 여부는 이 결과만으로 알 수 없어요. 결과 열기 버튼으로 실제 표시를 따로 관찰해보세요 | 태그 판정과 수동 브라우저 관찰은 별도 |
| IDOR / IDOR-04 | 요청한 주문1043의 소유자는2001이에요. 이번 요청의 소유자 주장1은 그 값과 달라 반환이 차단됐어요. 주장값이 실제 인증 정보인 것은 아니에요. 두 번호의 출처를 비교해보세요 | 객체번호·현재 더미 사용자·소유자 주장을 구분 |
| SSRF / SSRF-03 | URL의 사용자 정보에 신뢰 문자열이 있고 파싱한 호스트는127.0.0.1이에요. 부분 문자열 정책을 통과해 루프백용 더미 응답이 표시됐어요. @ 뒤 호스트를 확인해보세요 | 실제 DNS/HTTP 요청·공개/안전 주소 검증은 하지 않음 |
| CMDi / CMD-05 | 첫 명령 경계는 &&지만 Normal 차단을 일으킨 문자는 뒤의 ;예요. 모의 명령의 표준 출력은 없고 표준 오류에 차단 안내가 있어요. ; 위치를 확인해보세요 | 첫 경계·차단 원인·stdout/stderr를 나눔 |
| Linux / LINUX-05 | 필요한 조각은 있지만 이 퀴즈가 정한 명령→옵션→경로 순서와 달라요. 실제 Linux 문법 오류를 판정한 것은 아니에요. 옵션과 경로의 순서만 바꿔 비교해보세요 | 퀴즈 목표 불일치와 일반 셸의 유효성 구분 |
| 권한 Easy / PERM-03 | 가상 student가 report.txt를 읽으려 했어요. 이 파일은 mentor 소유이고 소유자에게만 읽기 권한이 있어 모형이 읽기를 거부했어요. 파일의 소유자와 현재 사용자를 비교해보세요 | 현재 모형의 대표 거부 사례. 키보드 초점 설명과 Lens·TUI 대조 완료, 전체 조작 방식 검증은 별도 |

SQL~Linux 사례 ID는 [41개 고정 사례](../verification/2026-10-27-lens-review-cases.json), PERM ID는 [권한9개 사례](../verification/2026-10-27-permissions-review-cases.json)를 가리킨다.
코드·실제 화면 기록은 [통합 검토](../verification/2026-10-27-lens-narrative-review.md)를 참조한다.

## 7. 검토 방법과 기록 양식

문구의 모양만으로 통과시키지 않고 실제 입력과 결과를 함께 확인한다.

    유형 / Easy 또는 Normal / 실제 입력:
    원문과 실제 사용값:
    선택 행·사용자·대상·비교 규칙:
    실제 상태·반환 수·표준 출력·표준 오류:
    설명에서 연결한 내용 / 모르는 범위:
    작은 다음 관찰:
    위치·행 변경·단서 버튼·원문/해설 일치:
    검사 방법·근거 파일 / 검토자 / 미확인 항목:

다음 조건을 실제로 확인해야 해당 사례를 통과로 기록한다.

- 원문·사용값·자리·대상·결과가 서로 일치한다.
- 일반 입력·오류·차단·미지원·목표 달성의 의미를 섞지 않는다.
- 분석 단계가 새 실행 결과를 만들어 말하지 않는다.
- 전문 용어는 그 사례 안에서 쉬운 뜻을 붙인다.
- 다음 행동 하나가 현재 UI에서 가능하고 표시 위치를 잘못 가리키지 않는다.
- 모형이 모르는 구문을 아는 척하지 않는다.
- Easy/Normal의 기본 안내와 선택형 단서 차이를 확인한다.
- 터미널의 원문·밑줄·짧은 설명·Lens·TUI가 제공되는 경우 같은 시도·원인을 설명한다.

## 8. 이번 문서 자체의 검토 상태

AI가 기존 lens 필드, GuidedLesson의 예시/단서 노출과 단계 완료 조건, 고정41사례를 대조해 작성했다.
41사례의 실행 상태·분석 단계·사용값 기준 focus 범위·모형 표시 필드를 다시 점검했다. 이것은 문안의 교육 효과나 모든 UI 조합을 입증하는 시험이 아니다.

공통 기준의 명문화와 기존 사례에 대한 AI 대조는 완료했다. 본인·팀의 문구 검토는 남아 있다.
권한 Easy 문안의 본인·팀 최종 검토, 전체13개 흐름 최종 확인, CSV 범위 검토, 원격 공유와 이슈 전체 완료는 별도로 남는다.
