# PayloadLab 주간 진행 보고

**보고 기간:** 2026-09-07 ~ 2026-09-11

**전체 상태:** 🟢 정상 진행

**이번 주 한 줄 요약:** 보안 입문자를 위한 학습 서비스의 목적, 화면 흐름, 초기 범위를 문서로 정리하고 1차·2차 MVP 및 최종 결과물의 기준을 설계했습니다.

## 1. 이번 주에 한 일

- **프로젝트 문서와 작업 흐름을 정리했습니다.** 기획, 자료조사, 의사결정, 회의 기록을 `docs/`에 나누고, 할 일과 논의는 Issue, 결과물 변경은 Pull Request로 연결하는 기준을 마련했습니다. 이후 진행 내용과 근거를 한곳에서 확인할 수 있게 하기 위함입니다.
- **1차 MVP의 학습 흐름을 설계했습니다.** 사용자는 공격 유형과 난이도를 고르고 입력을 시도합니다. 그 뒤 입력값이 교육용 코드·쿼리에 결합되는 모습, Lens의 실수 위치·이유 설명, 결과 다이어그램을 보고 다시 입력을 고치는 흐름을 목표로 정했습니다.
- **단계별 범위와 최종 결과물 기대치를 분리했습니다.** 첫 단계는 SQL Injection·Reflected XSS·IDOR의 입문 학습 흐름을 우선 검증합니다. SSRF 모의 시나리오와 리눅스 명령어 빈칸 퀴즈는 두 번째 단계 후보로 두고, 첫 단계의 설명 품질이 확인된 뒤 추가 여부를 판단합니다.

## 2. 단계별 결과물 설계

| 단계 | 목표 | 이번 주에 정한 결과물 기준 |
| --- | --- | --- |
| 1차 MVP | 입문자가 한 번의 입력을 통해 공격 원리를 이해하는 흐름 검증 | SQL Injection·Reflected XSS·IDOR, 유형·난이도 선택, 입력창, Lens, 입력이 포함된 결과 다이어그램, 재시도 흐름 |
| 2차 MVP | 첫 학습 흐름을 유지하면서 연습 범위 확장 | SSRF 교육용 모의 시나리오, 리눅스 명령어 가상 파일 시스템·빈칸 퀴즈를 후보로 검토 |
| 최종 결과물 | 초보자가 설치 없이 반복 연습할 수 있는 교육용 웹 서비스 | 유형 목록과 난이도 구분, 안전하게 제한된 입력 시뮬레이션, Lens 설명, 다이어그램, 오류·안전·사용성 점검, 사용자 가이드와 발표 자료 |

## 3. 토의를 통해 정리된 방향

| 논의 주제 | 정리한 방향 | 이유 |
| --- | --- | --- |
| 주요 사용자 | 보안 전공 심화 학습자보다 보안 입문 희망자 | 기존 취약점 실습 환경은 설치와 첫 접근 자체가 어려울 수 있기 때문 |
| 핵심 학습 방식 | 정답 제시보다 입력의 실수 위치와 이유를 설명 | 사용자가 다음 입력을 스스로 고치며 반복 학습하도록 하기 위해 |
| 안전 범위 | 실제 외부 대상을 공격하지 않고, 정해진 교육용 시나리오 안에서 결과를 시뮬레이션 | 학습 목적을 유지하면서 오용 가능성을 줄이기 위해 |
| 확장 기능 | SSRF·리눅스 퀴즈는 첫 단계 이후에 검토 | 핵심 세 유형의 화면·설명 품질을 먼저 확보하기 위해 |

## 5. 다음 주에 할 일

- 1차 MVP의 세 유형에 대해 학습 목표, Easy/Medium 구분, 입력 예시, Lens 설명 기준을 문서로 확정합니다.
- 화면 설계 결과를 바탕으로 유형 선택 → 입력 → Lens → 다이어그램 → 재시도 흐름의 프로토타입 요구사항을 구체화합니다.
- 교육용 시뮬레이션의 입력 제한과 Docker 실행 환경의 안전·재현성 확인 항목을 점검합니다.

## 6. 교수님 의견 요청
