# PayloadLab 주간 진행 보고

**보고 기간:** 2026-09-01 ~ 2026-09-11

**전체 상태:** 🟢 정상 진행 (기획안은 교수님 검토 전)

**이번 주 한 줄 요약:** 프로젝트를 시작하기 위한 GitHub 운영 구조와 문서 체계를 설계하고, 1차·2차 MVP 및 최종 결과물은 팀 내부 기획 초안으로 정리했습니다.

## 1. 이번 주에 한 일

- **프로젝트를 위한 GitHub 운영 구조를 설계했습니다.** 할 일과 논의는 Issue, 조사·결정 근거는 `docs/`, 실제 변경은 Pull Request로 연결하고, 역할·Assignee·주간 보고를 같은 흐름에서 확인하도록 정리했습니다.
- **문서와 보고서 체계를 설계했습니다.** 기획, 자료조사, 의사결정, 회의·교수님 보고 문서를 분리하고, 이후 매주 복제해 쓸 주간 보고 공용 양식을 마련했습니다.
- **1차 MVP의 화면 흐름과 단계별 범위를 팀 내부 기획 초안으로 정리했습니다.** 사용자는 유형과 난이도를 고르고 입력한 뒤, Lens와 결과 다이어그램을 보며 다시 입력을 고치는 흐름을 우선 검토합니다.

## 2. 팀 내부 단계별 결과물 계획

아래 범위는 팀 내부 기획 초안이며, 교수님 검토와 이후 자료조사 결과에 따라 조정합니다.

| 단계 | 목표 | 이번 주에 정한 결과물 기준 |
| --- | --- | --- |
| 1차 MVP | 입문자가 한 번의 입력을 통해 공격 원리를 이해하는 흐름 검증 | SQL Injection·Reflected XSS·IDOR, 유형·난이도 선택, 입력창, Lens, 입력이 포함된 결과 다이어그램, 재시도 흐름 |
| 2차 MVP | 첫 학습 흐름을 유지하면서 연습 범위 확장 | SSRF 교육용 모의 시나리오, 리눅스 명령어 가상 파일 시스템·빈칸 퀴즈를 후보로 검토 |
| 최종 결과물 | 초보자가 설치 없이 반복 연습할 수 있는 교육용 웹 서비스 | 유형 목록과 난이도 구분, 안전하게 제한된 입력 시뮬레이션, Lens 설명, 다이어그램, 오류·안전·사용성 점검, 사용자 가이드와 발표 자료 |

## 3. 팀 내부 토의를 통해 정리한 가설

| 논의 주제 | 정리한 방향 | 이유 |
| --- | --- | --- |
| 주요 사용자 | 보안 전공 심화 학습자보다 보안 입문 희망자 | 기존 취약점 실습 환경은 설치와 첫 접근 자체가 어려울 수 있기 때문 |
| 핵심 학습 방식 | 정답 제시보다 입력의 실수 위치와 이유를 설명 | 사용자가 다음 입력을 스스로 고치며 반복 학습하도록 하기 위해 |
| 안전 범위 | 실제 외부 대상을 공격하지 않고, 정해진 교육용 시나리오 안에서 결과를 시뮬레이션 | 학습 목적을 유지하면서 오용 가능성을 줄이기 위해 |
| 확장 기능 | SSRF·리눅스 퀴즈는 첫 단계 이후에 검토 | 핵심 세 유형의 화면·설명 품질을 먼저 확보하기 위해 |
