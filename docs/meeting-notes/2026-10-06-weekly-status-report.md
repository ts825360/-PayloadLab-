# PayloadLab 주간 진행 보고

**보고 기간:** 2026-10-01 ~ 2026-10-06  
**전체 상태:** 🟢 정상 진행  
**이번 주 한 줄 요약:** 기존 기획·조사 문서를 바탕으로 1차 MVP의 문서 체계를 정리하고, SQL Injection·Reflected XSS·IDOR의 UI와 기술 구현 상태를 확인했습니다. 다음 주에는 유형별 흐름을 통합 검증합니다.

## 1. 이번 주에 한 일

- **기존 문서와 GitHub 기록을 정리했습니다.** 팀원이 작성한 유형별 조사와 기획 문서를 기준으로 1차 MVP 범위, 학습 흐름, Lens 설명 방향, 데이터 흐름 다이어그램의 기준을 한 흐름으로 확인했습니다.
- **1차 MVP의 UI 구성을 확인했습니다.** 공격 유형 목록, Easy/Medium 난이도 선택, 공격 입력창, Lens 피드백, 결과·데이터 흐름 다이어그램이 한 학습 흐름으로 연결되는 화면 구조를 정리했습니다.
- **핵심 기술 구현을 확인했습니다.** SQL Injection·Reflected XSS·IDOR 실습 로직과 입력 결과, Lens 규칙, 흐름 데이터 구조가 구현되어 있으며 백엔드 테스트 26개가 통과했습니다. 다만 전체 화면·Docker 환경을 하나의 사용자 흐름으로 검증하는 작업은 다음 주로 남겼습니다.

## 2. 토의를 통해 확정한 일

| 논의 주제 | 팀의 결정 | 결정 이유 |
| --- | --- | --- |
| 1차 MVP 범위 | SQL Injection·Reflected XSS·IDOR 중심으로 진행 | 입문자가 데이터베이스·브라우저·인가 흐름을 비교해 학습하기에 적절한 대표 유형이기 때문 |
| 설명 방식 | 성공 여부만 보여 주지 않고, 입력 위치·부족한 요소·필요한 이유를 Lens로 설명 | 사용자가 실패 원인을 바탕으로 다음 입력을 스스로 수정하도록 하기 위해 |
| 확장 기능 | SSRF와 제한된 Linux 명령어 퀴즈는 1차 MVP 검증 이후 진행 | 핵심 세 유형의 UI와 설명 품질을 먼저 확인하기 위해 |
| 안전 범위 | 정해진 교육용 시나리오와 더미 데이터 안에서만 결과를 재현 | 실제 외부 대상을 공격하는 기능으로 확장되지 않도록 하기 위해 |

## 3. 아직 해결되지 않은 일

| 내용 | 현재 상태 | 다음 행동 |
| --- | --- | --- |
| 유형별 입력 → Lens → 다이어그램 연결 | 개별 화면과 로직은 확인했으나 모든 유형·난이도의 연결 검증은 남음 | 동일한 테스트 시나리오로 성공·실패·재시도 흐름을 점검 |
| 프론트엔드와 백엔드 결과 일치 여부 | 백엔드 단위 테스트는 통과했으나 전체 브라우저 흐름은 추가 확인 필요 | Docker 실행 후 실제 입력값, Lens 문장, 다이어그램 결과를 대조 |
| 예외 입력과 회귀 여부 | 일부 유형별 규칙은 구현되어 있으나 공통 검증표가 아직 없음 | 유형·난이도별 정상 입력, 실패 입력, 빈 입력, 경계 입력을 표로 검증 |

## 4. 다음 주에 할 일

- SQL Injection·Reflected XSS·IDOR의 Easy/Medium 시나리오를 Docker 환경에서 처음부터 끝까지 통합 검증합니다.
- 입력값이 실제 결과 화면과 Lens, 데이터 흐름 다이어그램에 동일하게 반영되는지 확인합니다.
- 예외 입력과 기존 기능 회귀를 점검하고, 발견된 문제는 Issue와 Pull Request로 기록합니다.
- 통합검증 결과를 바탕으로 1차 MVP의 완료 여부와 SSRF·Linux 확장 착수 조건을 결정합니다.
