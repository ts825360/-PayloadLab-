## 현재 실행과 저장 상태

이번 준비 단계에서 로컬 프론트 http://127.0.0.1:5173/ 응답200, API8001 health=ok, 등록 실습13개를 확인했다. 이는 아래 실제 조작 검사를 대신하지 않는다.
이 표를 준비할 때 터미널 수정fd106c9와 CSV 근거eedd3a9는 로컬 commit·미push 상태였다. 이후 최신 fetch에서 두 커밋의 원격 공유를 확인했으며, 사용자 명시 요청에 따라 이 표/재확인 기록만 새로 commit·push한다. 실제 전송 결과는 Git의 HEAD/원격 일치로 확인하며 직접 검증 완료와 구분한다. 작업 원문SQLite 참고 Markdown1개는 여전히 부재이고 그 삭제는 commit에 포함하지 않았다.
이 원문 부재는 참고 CSV의 파일 기반 검사 문제이며, 현재 SQL 실습 서버가 실행되지 않는다는 뜻이 아니다. Git 보관 원문을 이용한 별도 출처·재생성 근거는 [검증 기록](2026-10-27-csv-snapshot-verification.md)에 있다.

PC의 로컬 실습 화면에서 ‘권한상승 기초 → Easy’를 선택한다. 기존 기록 때문에 root이면 exit를 먼저 실행한다. whoami로student를 확인하고 cat /lab/report.txt를 실행한다. 원문은 cat: /lab/report.txt: Permission denied다.

## 실제 조작 — 수행한 항목만 기록

- [ ] PC 마우스: Permission denied 밑줄에 마우스를 올린다. 현재student와 파일 소유자mentor, 다른 사용자 읽기 불가라는 짧은 설명이 표시되는지 확인한다. 마우스를 떼면 닫히는지도 확인한다.
- [ ] PC 클릭: 같은 밑줄을 누른다. Lens가 같은 시도의 입력·사용자·파일·거부 이유를 설명하는지 확인한다. 입력 초안이나 원문 출력이 바뀌면 실패로 기록한다.
- [ ] 원문 보존: 오류 원문을 선택/복사했을 때 해설이 섞이지 않는지 확인한다. 밑줄 설명과 raw출력은 별도여야 한다.
- [ ] 키보드: Tab으로 진단에 초점을 주고 설명을 읽는다. Escape는 짧은 설명만 닫고 터미널 입력·기록은 남기는지 확인한다.
- [ ] 실제 브라우저200% 확대: 브라우저의 확대 설정이200%라고 표시되는 상태에서 같은 입력·오류·Lens를 확인한다. 입력과 실행 버튼을 사용할 수 있고 설명이 화면 밖으로 잘리지 않는지 확인한다. 단순 창 크기 변경이나 CSS 확대를200% 확인으로 기록하지 않는다. 마친 뒤 원래 확대율로 돌린다.
- [ ] 화면 크기 변경: 긴 초안을 입력하되 실행하지 않고 창을 좁혔다 넓힌다. 글자가 보존되고 입력칸 높이·밑줄이 따라오는지, 스크롤 뒤 밑줄이 다른 줄에 남지 않는지 확인한다.
- [ ] 실제 터치: 접근 가능한 실제 터치 기기에서 밑줄을 눌러 동일 원인의 Lens로 연결되는지 확인한다. 화면 밖 설명·다른 시도로의 연결·초안 소실 여부를 확인한다. 바깥 누르기와 길게 누르기의 관찰 결과도 적는다. PC 마우스 클릭이나 자동 touch 이벤트 검사로 대신 체크하지 않는다.

## 본인·팀 문안 검토

[13개 최초 안내·27단계의 기존 대조](2026-10-27-learning-flow-review.md)와 실제 화면을 읽고 다음을 본인 말로 설명한다.

- [ ] SQL 일반 이름은 누구와 비교해서 거짓인지, 고정된 틀린 비밀번호와 AND 때문에 왜0행인지 설명할 수 있다. 문법 오류와 일반 이름/조건 불충족을 구분한다. Normal은 내가 쓴 값과 필터 후 사용값을 구분한다.
- [ ] XSS의 태그 형태 인식과 실제 브라우저 실행을 구분한다. IDOR의 주문번호·현재 사용자·실제 소유자·요청의 소유자 주장을 구분한다.
- [ ] SSRF/CMDi의 파싱·정책/명령 경계와 가상 출력, Linux 퀴즈의 정답 비교, 권한의 가상 상태 변화가 각각 어떤 결과인지 설명할 수 있다. 실제 네트워크/셸/OS 권한 실행으로 설명하지 않는다.
- [ ] 다음 시도가 현재 결과에서 바로 할 수 있는 작은 관찰인지 확인한다. 해석하지 못한 입력의 원인을 단정하는 문구가 있으면 입력·화면과 함께 남긴다.
- [ ] CSV attack라벨은 시도 문맥이며 실습 성공이나 입력자의 악의가 아님을 설명할 수 있다. benign/uncertain도 문맥과 함께 읽고, Git 원문 기준 재현과 작업 폴더 원문 부재를 구분한다.
