## #6용 — DEC-03/04 정책 선택 요청

#44의 요청량·동시 실행·프록시 정책을 검토할 수 있도록 프로젝트 근거를 정리했습니다. N과 최종값은 태성님이 결정할 사항으로 남겨두었습니다.

현재13랩·27단계 안내와 기존 제한 경계68사례를 별도 loopback 프로세스에서 동시1/2/4/8개로 측정했습니다. 최신 admission 포함816건은 모두 HTTP200이며, 각 프로파일의 재귀 SQL3건은 의도한 자원중단 응답입니다. 브라우저 실행/공개 부하 시험은 아닙니다.

후보식:
- 자동분석320ms에서 ceil(1000/320)=4. analyze/attempt/render 분류별 초당4N·burst N.
- attempt/render도 같은 수정 주기의 조작1회를 허용하자는 정책 선택입니다. 기존 UI의 물리적 상한이라는 뜻은 아닙니다.
- metadata는 처음N개 작업공간을 함께 열고 재연결은 각초당1회 목표: 초당N·burst N.
- 전체 labs는 초당13N·burst4N, 동시 A안2N/B안3N 비교·분류별N, 앱 대기열0.
- IP별 정책은 기본 미사용 제안. 학교 NAT의 여러 사용자를 한 사람으로 보지 않고 전체/분류 합계는 IP 변경에도 유지합니다.
- 요청 완료320ms는 후보 목표이며 hard timeout이 아닙니다. 본문/전체 hard timeout은 운영 근거 전 미정입니다.

CPU는 서버 프로세스 전체의 요청당 평균 중 최대8.961ms였습니다. 1CPU의50%를 우선 검토선으로 두자는 여유 정책 아래 N=1은13rps·동시 A2/B3·계획11.6%, N=4는52rps·동시 A8/B12·계획46.6%입니다. N=8은104rps·동시 A16/B24·93.2%, N=16은208rps·동시 A32/B48·186.4%라 관측 범위/여유선을 넘습니다. 어느 인원도 확정한 것이 아니며 평균 기반 계획을 최악 입력 보호나 지원 인원 보장으로 쓰지 않습니다.

Windows Python3.13·8논리CPU 측정이며 Compose1CPU/256m은 적용하지 않았습니다. 목표 환경에서 재검증해야 합니다. 12개 가상 시간 시나리오5,858입장은 허용되고 IP 변경 후 상한·슬롯 반납 후 회복도 확인했지만 실제 동시 사용자 용량 시험과는 다릅니다.

2차 검증에서 A안2N은 응답161ms에도 이전 미리보기와 다음 분석/실행이 겹쳐 정상 모형 요청이 거부되는 반례를 확인했습니다. B안3N은 응답320ms까지의 가상 모형에서 통과했지만 실제 처리 용량은 검증하지 않았고, N=4이면12동시로 현재 실측8 밖입니다. A/B는 미선택입니다. 전체13N/4N은 API별 상한의 합계와 같으며 더 엄격한 독립 서비스 상한은 아닙니다. 전체 burst만 줄인 별도 대조4건으로 모듈의 독립 집계를 확인했습니다.

검토 요청: N·정상 탭/조작 범위·숫자와 여유폭·time limit·신뢰 프록시/원본 API 경계를 선택하거나 근거와 함께 보류해 주세요. 기본 앱에 적용하지 않았습니다.

## #24용 — 검증 범위와 운영 잔여

#44의 단일 프로세스 모듈/검토 앱·입력/출력 취소 정리까지 구현했고 직전 backend433개가 통과했습니다. 이번 정책 단계에서는 제품 소스 수정 없이 최신 HTTP816건 비용 측정과 인원별 가상 재생을 수행했습니다.

- 기본 app.main.app과 Compose는 변경하지 않았고 미승인 후보를 활성화하지 않았습니다.
- 로컬 검토는 proxy_headers=False·빈 신뢰 목록·worker1입니다. 운영 프록시/직접 원본 포트 차단·다중 worker 공유 집계 완료를 주장하지 않습니다.
- peer 기본 미사용 제안과 서비스/API 합계 제한을 구분했습니다. 실제 학교 NAT 이용량·개인별 공정성 보장은 미검증입니다.
- 앱 대기열0과 Uvicorn backlog2048·keepalive5초를 구분했습니다. backlog는 연결 대기, keepalive는 유휴 연결이며 본문/전체 작업 timeout이 아닙니다.
- 목표1CPU/Python3.12·본문/전체 deadline·강제 종료·운영 경보/비용·긴급 중지·브라우저·보호 범위 밖 endpoint의 정책이 남았습니다.

#12/#24/#6에서 실제 운영 담당자와 경보·긴급 중지 책임, 원본 API 접근 정책과 검증 대상을 기록해야 합니다. 태성님은 정책 최종 검토자이며 실제 운영 담당자는 이번 문서로 임의 배정하지 않습니다.

앱 제한을 DDoS 방어 보장이나 공개 승인으로 표현하지 않습니다. 실제 검증한 항목만 체크하고 전체 기준 전 #44를 종료하지 않습니다. 상세 로컬 근거는 위 정책 문서와 docs/verification/2026-10-29-issue44-cancellation-recheck.md에 있습니다. Refs #44.
