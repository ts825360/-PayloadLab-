배포·재현성·복구는 기능 B/H와 보안 O/T에 포함한다. 별도 네 번째 파트로 늘리지 않는다. 기능별로 검증·수정한 뒤 공개 후보 버전을 대상으로 마지막 통합 확인을 한다. 종료된 #23은 과거 로컬 통합 기록으로 보존하며 이번 문서만으로 재개하거나 공개 승인으로 바꾸지 않는다.

- 각 항목은 **미실시 / 통과 / 실패 / 해당 없음 / 자문 대기** 중 하나로 기록한다. 초기 체크는 모두 비워 둔다. 과거 100개·54개 테스트 통과 기록을 이번 체크 전체 통과로 옮기지 않는다.
- `[x]`는 해당 항목의 시험과 근거 기록이 완료된 경우에만 사용한다. 해당 없음은 기능 부재·코드 근거와 검토자를 적고, 미실시·자문 대기를 통과로 바꾸지 않는다.
- 결과에는 항목 ID, 실제 수행자·검토자, 코드 SHA·환경·시간, 입력/절차, 기대·실제 결과, 증거, 남은 문제를 남긴다. 자동 테스트·HTTP·브라우저·부하 검증을 구분한다.
- 이슈 댓글의 체크리스트는 담당 진행표다. 문서의 항목 정의를 바꾸면 해당 이슈 댓글에 변경 ID와 이유를 남긴다. 결과를 docs에 남길 경우 이슈에도 링크한다. 타인의 체크·기여를 대신 꾸며 쓰지 않는다.
- 외부 공격·데이터셋 자동 실행은 금지한다. 보안·부하 시험은 승인된 격리 환경, 통제된 로컬 수신점/요청 가로채기, 합의된 부하·중단 조건으로만 한다. 이 문서는 시험 실행이나 공개 배포의 허가가 아니다.

## 기능 A–H — #22

### A. 범위·유형·난이도

- [ ] A-01 API 목록과 UI 목록을 대조한다. SQLi·Reflected XSS·IDOR·SSRF·CMDi·Linux는 Easy/Normal, 권한상승은 Easy만 제공되어 현재 13개 지원 조합이 일치한다.
- [ ] A-02 모든 유형·난이도를 순서대로 전환한다. Normal은 API의 medium ID와 연결되고 이전 유형의 입력·결과가 현재 유형의 결과처럼 섞이지 않는다.
- [ ] A-03 권한상승 Normal을 선택·직접 호출한다. 화면은 구현 예정임을 설명하고 미등록 API는 통제된 404로 응답하며 연결 장애나 성공으로 표시하지 않는다.

### B. 설치·실행·재현성

- [ ] B-01 별도 깨끗한 환경에서 README만 따라 의존성 설치·Compose 빌드·기동을 수행한다. 누락 파일·개인 절대 경로·비밀값 없이 재현되고 버전을 기록한다.
- [ ] B-02 health·랩 목록·프론트 HTTP·실제 포트 바인딩을 확인한다. 포트 충돌은 원인과 복구 방법을 안내하고 다른 프로젝트 프로세스를 임의 종료하지 않는다.
- [ ] B-03 정지·재시작·컨테이너 재생성 후 대표 실습을 재시도한다. 로컬/공개 후보 구성을 구분하고 공개 후보 브라우저의 API가 방문자 PC의 localhost를 잘못 가리키지 않는다.

### C. 분석·실행·공통 계약

- [ ] C-01 입력 분석만 호출한다. phase=analysis이고 실행 결과·반환 행·미래 권한 상태를 미리 성공한 것처럼 출력하지 않는다.
- [ ] C-02 13개 조합의 실행 응답을 형식 검사한다. raw/effective input, 조립 값·범위, Lens, 유형별 결과가 정의한 계약과 일치하고 필수 필드 누락은 탐지된다.
- [ ] C-03 그래프의 노드 ID 중복·끊긴 edge·범위를 벗어난 code_line/강조 위치를 검사한다. 입력값이 실제 조립 값의 올바른 위치에 표시된다.
- [ ] C-04 메타데이터·API 오류·구형 응답을 대입한다. 공통 UI가 예외로 멈추거나 누락 데이터를 임의의 성공 값으로 보완하지 않는다.

### D. SQL 학습 결과

- [ ] D-01 빈 값·admin·박태성을 입력한다. 문자열 비교 대상, 고정된 비밀번호 조건, 0개 결과를 구분하고 정상 이름 입력을 문법 오류나 공격으로 단정하지 않는다.
- [ ] D-02 정상 연결 연산자 입력과 OR를 뺀 입력을 비교한다. 문자열 경계/연산자 문제의 위치·이유가 실제 SQLite 해석과 일치하며 연속 따옴표의 의미도 잘못 설명하지 않는다.
- [ ] D-03 대표 성공·문법 오류·결과 없음·주석/줄바꿈·Normal 필터 전후를 검사한다. 실제 행 수와 설명이 맞고 주석이 모든 성공 입력에 필수라고 단정하지 않는다.
- [ ] D-04 지원하는 조건식과 지원 범위 밖의 식을 비교한다. 조건 트리는 실제 행과 일치하고, 모르는 식은 추측한 다이어그램 대신 지원 범위를 설명한다.

### E. XSS 학습 결과

- [ ] E-01 일반 검색어·완성/미완성 script 태그·대소문자 변형을 입력한다. Easy/Normal의 필터 전후와 Lens가 실제 처리와 일치한다.
- [ ] E-02 태그 인식과 브라우저 JS 실행을 구분한다. 서버의 recognized 결과만으로 실제 실행이 검증됐다는 성공 문구를 표시하지 않는다.
- [ ] E-03 공개 실행 방식이 결정되면 모의 화면 또는 격리 실행 화면을 확인한다. 일반 코드·설명 영역은 입력을 HTML로 실행하지 않고, 실제 실행은 정한 명시적 동작에서만 발생한다.

### F. IDOR 학습 결과

- [ ] F-01 본인 주문·타인 주문·없는 주문·잘못된 타입을 요청한다. 대상 유무·소유 관계·반환 여부와 Lens가 일치하고 잘못된 값으로 서버가 멈추지 않는다.
- [ ] F-02 Normal에서 claimed_user_id를 비우거나 다르게/맞게 보낸다. 더미 시나리오의 불완전한 검사와 실제 소유자를 구분하고 거절된 자료를 반환됐다고 표시하지 않는다.
- [ ] F-03 화면에서 도달할 수 없는 조건과 규칙을 조사한다. 정수/문자 식별자의 설명이 실제 더미 데이터 범위와 일치하며 유지/제외 결정을 기록한다.

### G. 확장 모형·가상 터미널

- [ ] G-01 SSRF의 일반 URL·loopback·userinfo·비정상 포트·비HTTP를 비교한다. 문자열 파싱과 더미 응답만 사용하며 실제 DNS/HTTP 호출이 없다는 시험 근거를 남긴다.
- [ ] G-02 CMDi에서 정상 호스트·허용 구분자/명령·미지원 명령·Normal 필터를 비교한다. 더미 stdout/stderr가 맞고 실제 셸·프로세스 호출이 없음을 확인한다.
- [ ] G-03 Linux Easy/Normal의 정답·오답·공백 변형·지원하지 않는 명령을 비교한다. 정한 토큰 퀴즈로 채점하고 호스트 파일을 읽거나 변경하지 않는다.
- [ ] G-04 권한 Easy의 접근 거부→가상 helper→더미 파일 읽기→exit를 시험한다. 클라이언트 권한 플래그를 믿지 않고, 미지원 명령 이후에도 정상 명령이 동작하며 실제 OS 권한은 변하지 않는다.

### H. 상태·오류 복구·회귀

- [ ] H-01 빠르게 입력·전환하고 늦은 응답·연속 실행을 대입한다. 이전 요청이 현재 화면을 덮지 않고 실행 중 중복·오래된 분석을 구분한다.
- [ ] H-02 API 중단·요청 실패·새로고침·재시도·과거 시도 비교를 수행한다. 현재/이전 입력과 결과의 소속이 명확하고 서버 영구 기록이 없다는 현재 모델과 일치한다.
- [ ] H-03 공개 후보 SHA에서 백엔드/프론트 전체 테스트·빌드·13개 랩 스모크와 데이터셋 manifest/출처 검사를 수행한다. 결과·실패·미실시를 구분하고 마지막 통합 근거를 남긴다.

## 보안 I–T — #24

아래는 조치 후 확인할 기준이다. SQLi/XSS 문자열 자체를 일괄 차단하는 대신 실습 실행 경계와 서비스 보호를 검증한다. WAF 예외가 필요하면 실습 경로·필드로 한정하고 전역 보호를 해제하지 않는다.

### I. 서버 입력 검증·SQL 경계 — A05

- [ ] I-01 UI를 우회해 모든 analyze/attempt/render에 경계값 이하·같음·초과 길이, 잘못된 타입·문자 인코딩·과다 필드를 보낸다. 서버에서 정한 필드/전체 요청 상한을 강제한다.
- [ ] I-02 중첩 JSON·배열·권한 history의 개수/총량/허용 명령을 검사한다. 거절된 입력이 잘려서 정상 명령·권한 변경으로 처리되지 않는다.
- [ ] I-03 SQLite의 허용 연산·실행시간/연산량·행 수·응답 크기를 작은 제한값으로 시험한다. 중단 시 실제 계산과 연결이 정리되고 다른 요청의 서비스가 유지된다.
- [ ] I-04 학습용 쿼리·명령을 실제 서비스 DB·OS·호스트 파일·외부 HTTP에 연결할 수 없는지 검토한다. 더미 데이터 노출을 실제 사용자 데이터 접근 허용과 혼동하지 않는다.

### J. XSS 실행 문서 격리 — A02/A05

- [ ] J-01 DEC-01에 따른 공개 실행 방식을 확정하고 직접 render URL·iframe 경로를 각각 시험한다. 실행을 끈 공개판은 원본 실행을 우회해 열 수 없고, 유지하는 판은 응답 정책까지 적용된다.
- [ ] J-02 실제 실행을 유지한다면 별도 origin·CSP 응답 sandbox·쿠키/저장소·상위 페이지/다른 프레임 접근 제한을 브라우저에서 확인한다. iframe 속성만으로 직접 접근이 보호된다고 판단하지 않는다.
- [ ] J-03 실행 HTML의 fetch·이미지·스크립트·폼·중첩 frame·이동을 통제된 수신점/가로채기로 검사한다. 정한 목적지 외 통신이 차단되며 시험 중 외부 대상에는 요청하지 않는다.
- [ ] J-04 모달 반복·장시간 실행의 위험, 실행 종료/프레임 제거와 브라우저별 한계를 승인된 작은 시험으로 기록한다. 서버 컨테이너 제한이 사용자 브라우저 자원까지 보호한다고 주장하지 않는다.

### K. 접근통제·인증 — A01/A07

- [ ] K-01 공개·관리·사용자별 경로를 목록화하고 API 직접 호출로 권한을 확인한다. 없는 관리자/로그인 기능은 코드 근거로 해당 없음 처리한다.
- [ ] K-02 계정/세션이 있다면 다른 사용자의 식별자·객체·역할로 바꿔 접근한다. 서버가 소유자/역할을 검사하고 클라이언트의 user_id·history·성공 표시를 실제 권한 근거로 사용하지 않는다.
- [ ] K-03 인증이 있다면 무차별 대입·세션 고정·만료/철회·관리자 추가 인증을 검사한다. 쿠키 인증의 변경 API에는 CSRF 방어를 확인한다. CORS와 UI 숨김은 인증 대체가 아니다.

### L. IP 변경·프록시 우회 — A01/A02

- [ ] L-01 X-Forwarded-For/Forwarded 등 IP 헤더를 위조한다. 신뢰 프록시가 만든 값만 사용하고 임의 헤더로 제한·접근정책을 우회하지 못한다.
- [ ] L-02 원본 API 포트·대체 도메인·다른 경로로 직접 요청한다. CDN/프록시를 거치지 않고 제한을 회피하는 접근은 정한 배포 정책에서 차단된다.
- [ ] L-03 여러 통제된 클라이언트 IP·익명 세션 재발급·계정 변경을 모의한다. 식별자를 바꿔도 서비스 전체/고비용 API 상한은 유지된다. IP가 같다는 이유만으로 동일 사용자를 인증하지 않는다.

### M. DoS·자원·비용 제한 — A06/API4

- [ ] M-01 API별 지속 요청·짧은 burst를 합의한 소규모 부하에서 시험한다. 제한 초과 응답/대기 안내가 맞고 analyze 자동 요청도 정책에 포함된다.
- [ ] M-02 동시 실행·대기열·SQL 비용·응답 크기 상한을 검사한다. 앱 worker/인스턴스가 여러 개라면 제한 집계가 분산되어 의도보다 늘어나지 않는다.
- [ ] M-03 느린 연결·본문 수신·장시간 요청을 격리 환경에서 시험한다. 연결/실행 제한이 작동하고 호스팅 DDoS 방어·비용 경보·긴급 중지 책임자를 확인한다. 앱 rate limit을 대규모 DDoS 보장으로 보지 않는다.
- [ ] M-04 학교/NAT처럼 동일 IP의 정상 사용자와 학습 중 재시도를 모의한다. 합의한 이용량은 허용되고 IP 차단·CAPTCHA/WAF가 학습 입력을 불필요하게 막지 않는다.

### N. TTL·보관·만료

- [ ] N-01 서버 세션·토큰·임시 실습 자원·로그·캐시·제한 카운터·브라우저 상태를 목록화한다. 존재 여부와 만료/용량/삭제 주체를 구분하고, DNS TTL을 인증·DoS 대책으로 기록하지 않는다.
- [ ] N-02 세션/토큰이 있다면 미사용·최대 수명·만료 직전/직후·연장 상한을 가상 시각/짧은 테스트 설정으로 확인한다. 만료 값은 서버에서 재사용을 거절한다.
- [ ] N-03 임시 파일·사용자별 컨테이너가 있다면 브라우저 종료·프로세스 재시작·정리 실패 후에도 서버가 회수한다. 현재 공유 앱 컨테이너를 사용자 세션처럼 임의로 만료시키지 않는다.
- [ ] N-04 로그/캐시/제한 카운터의 합의한 기간·용량·항목 수와 삭제를 확인한다. 아직 없는 상태는 만들지 않고 해당 없음으로 기록하며 SQLite 요청 종료 수명과 시간 TTL을 구분한다.

### O. 운영 구성·컨테이너·네트워크 — A02

- [ ] O-01 공개 후보가 정적 프론트·운영 API로 동작하는지 확인한다. Vite dev/preview·reload·개발 소스 mount·불필요한 디버그 경로를 공개 서버로 사용하지 않는다.
- [ ] O-02 실제 컨테이너의 UID·capability·no-new-privileges·쓰기 가능한 경로·CPU/메모리/PID 상한을 확인한다. privileged·host network·Docker socket·불필요한 호스트 mount를 사용하지 않는다.
- [ ] O-03 내부·loopback·클라우드 메타데이터·외부 목적지로의 접근 정책을 안전한 통제 환경에서 확인한다. 실습 모형의 미호출과 컨테이너 네트워크 차단을 각각 기록한다.
- [ ] O-04 호스트 방화벽·보안그룹·포트·origin·CORS·API docs 노출 정책을 확인한다. 의도하지 않은 포트와 origin이 공개되지 않으며 CORS가 비브라우저 요청까지 막는다고 판단하지 않는다.

### P. HTTPS·비밀정보 — A04

- [ ] P-01 공개 후보에서 HTTPS·HTTP 전환·인증서·혼합 콘텐츠를 검사한다. HSTS 적용 범위/시점을 확인하고 브라우저가 올바른 공개 API 주소로 요청한다.
- [ ] P-02 토큰/비밀키·환경 파일·개인정보가 Git 작업 트리/필요한 이력 검사·이미지·번들·오류·로그에 포함되지 않는지 확인한다. 발견 시 단순 파일 삭제가 아닌 철회/교체까지 기록한다.
- [ ] P-03 인증 쿠키가 있다면 Secure/HttpOnly/SameSite·Domain/Path 범위와 민감 응답 캐시 정책을 확인한다. 로그인/민감정보 저장이 없으면 해당 없음 근거를 남긴다.

### Q. 의존성·공급망 — A03

- [ ] Q-01 프론트/Python/베이스 이미지 OS 패키지를 공개 후보의 실제 설치 버전으로 점검한다. 개발/실행 경로·플랫폼·악용 조건·조치와 수용 사유를 구분하고 audit 0개를 안전 보증으로 쓰지 않는다.
- [ ] Q-02 lockfile·설치 도구·Docker 빌드가 같은 버전 집합을 재현하는지 확인한다. 호환 업데이트 후 기능 회귀를 검사하고 비검증 자동 강제 업데이트는 하지 않는다.
- [ ] Q-03 코드·데이터셋·이미지의 출처/라이선스 고지·manifest와 빌드 문맥 제외 목록을 확인한다. 비밀값·로컬 도구·불필요한 생성물이 이미지에 들어가지 않는다.

### R. 데이터·배포 무결성 — A08

- [ ] R-01 클라이언트가 결과·사용자·난이도·history를 변조해도 실제 운영 권한이나 영구 성적의 근거로 신뢰하지 않는다. 가상 권한 helper와 실제 인증을 구분한다.
- [ ] R-02 공개 후보의 코드 SHA·빌드/이미지 식별자·설정·변경 검토 근거를 연결한다. 검증한 것과 실제 출시할 산출물이 다르면 재검증한다.
- [ ] R-03 API 필드·콘텐츠 형식·시나리오/데이터를 변조·누락했을 때 형식 검사와 안전한 오류 처리가 작동한다. 신뢰하지 않는 데이터를 코드/템플릿/배포 명령으로 실행하지 않는다.

### S. 로그·탐지·경보 — A09

- [ ] S-01 요청 급증·차단·반복 오류·만료·실행 한도 초과를 더미 표식으로 발생시킨다. 이벤트/요청 ID와 필요한 지표가 남고 담당자에게 시험 경보가 전달된다.
- [ ] S-02 로그 줄바꿈·HTML 표식과 민감정보 더미를 넣는다. 로그 위조/뷰어 실행·토큰/개인정보·불필요한 원문 공격 입력 기록을 방지하고 render URL query 기록도 확인한다.
- [ ] S-03 로그 열람 권한·반출·용량 회전·기간 삭제·경보 담당/대응 절차를 검사한다. 디스크 부족이나 로그 수집 장애가 서비스 무한 실패로 이어지지 않는다.

### T. 예외·안전 중단·복구 — A10

- [ ] T-01 JSON 파싱 오류·잘못된 메서드/타입·없는 랩·연결 실패·시간 초과를 대입한다. 내부 경로/stack trace/비밀값을 노출하지 않고 권한 검사 오류는 허용으로 처리하지 않는다.
- [ ] T-02 실행 취소·작업 실패·자원 부족을 제한된 환경에서 시험한다. SQL 연결/worker/대기열이 정리되고 실제 계산이 계속 남거나 무제한 재시작/재시도하지 않는다.
- [ ] T-03 잘못된 공개 후보를 중지·이전 검증 이미지로 되돌리는 절차를 격리 환경에서 연습한다. 영구 데이터가 있다면 복구까지 확인하고, 사고 보고·긴급 실습 중지 권한을 기록한다.

## 사용자 편의성 U–Z — #13

### U. 첫 진입·학습 안내

- [ ] U-01 처음 방문한 입문자가 설치/외부 검색 없이 유형·목표·입력 위치·다음 행동을 찾는 과정을 관찰한다. 별도 구두 설명이 필요했던 지점을 기록한다.
- [ ] U-02 지원하는 모든 Easy/Normal의 빈 입력 화면을 확인한다. 정의·성립 조건·입력→처리→결과·학습 목표·다음 행동이 있고 무의미한 대기 문구만 남지 않는다.
- [ ] U-03 Easy는 단계/추천 입력, Normal은 목표/선택형 힌트를 제공하는지 비교한다. 숨겨진 지식을 요구하거나 Normal에서 이유 설명 자체를 없애지 않는다.

### V. Lens 설명 품질

- [ ] V-01 박태성·따옴표·연산자 누락 같은 실패를 직접 입력한다. Lens가 어디를·왜·어떻게 관찰할지 실제 값과 위치로 설명하고 사용자를 틀렸다고만 표시하지 않는다.
- [ ] V-02 이미 충족한 조건·부족한 조건·미판정 상태를 구분한다. 기존 조건 체인과 현재 학습 단계/learning_trace가 충돌하거나 모두 실패처럼 보이지 않는다.
- [ ] V-03 문장 위치 보기를 누른다. 대응 부분이 같은 흐름에서 강조/확대되고 설명과 겹치지 않으며 돌아와 바로 수정할 수 있다. 사용자가 직접 위치를 찾아 헤매지 않는다.
- [ ] V-04 편집·분석·이전 결과·미지원 입력을 비교한다. 피드백이 어느 입력의 것인지 분명하고, 해석하지 못한 문장에는 확정적 원인 대신 지원 범위와 다음 확인점을 설명한다.

### W. 다이어그램·시각적 연결

- [ ] W-01 SQL·XSS·IDOR 대표 입력에서 입력값→조립 문장→처리→결과를 따라간다. 내 입력의 위치와 원인/결과 관계가 색상뿐 아니라 라벨로도 구분된다.
- [ ] W-02 SQL은 비교 계정/조건/반환 행, XSS는 서버와 브라우저 경계, IDOR는 요청자/소유자 관계가 각각 맞는지 본다. 실제 DB 내부 실행 순서를 보여준다고 오해하게 만들지 않는다.
- [ ] W-03 긴 입력·여러 줄·확대/비교·고정 Lens를 함께 시험한다. 핵심 내용이 가려지지 않고 불필요한 탭 이동/전체 페이지 스크롤 없이 다음 행동으로 연결된다.

### X. 키보드·접근성

- [ ] X-01 Enter 실행·Shift+Enter 줄바꿈·한국어 IME 조합·키 반복을 시험한다. 조합 완료 Enter가 실습 실행으로 오인되지 않고 실행 중 중복 제출을 방지한다.
- [ ] X-02 Esc→닫기 확인→Enter 종료, 취소/계속 학습을 각각 시험한다. 확인 전 닫히지 않으며 복귀 초점이 입력/원래 트리거로 돌아온다.
- [ ] X-03 마우스 없이 Tab/Shift+Tab/Enter로 주요 기능을 사용한다. 초점 표시·순서·버튼 이름·모달 초점 관리가 맞고 키보드 함정이 없다.
- [ ] X-04 스크린리더로 입력 라벨·오류·분석/실행 상태·표·그림 대체 설명을 확인한다. 상태가 전달되며 타이핑마다 긴 설명을 과도하게 반복하지 않는다.

### Y. 반응형·테마·동작

- [ ] Y-01 지원하기로 한 브라우저/화면에서 데스크톱·작은 창·모바일을 확인한다. 좁은 사이드바 로고, 입력/가상 키보드·하단 Lens·모달이 내용을 가리지 않는다.
- [ ] Y-02 Light/Dark의 실제 글자·코드·입력·상태·그래프 대비를 확인한다. 일반 텍스트 4.5:1, 큰 텍스트 3:1 기준과 색상 외 구분을 적용하고 브랜드 육안 확인도 남긴다.
- [ ] Y-03 200% 글자 확대·줄바꿈·긴 오류 문장을 시험한다. 내용/버튼이 잘리거나 겹치지 않고 핵심 조작을 유지한다.
- [ ] Y-04 reduced-motion 설정·전환 애니메이션·터치 조작을 확인한다. 이동 효과가 학습 초점을 빼앗지 않고 동작을 줄여도 기능이 사라지지 않는다.

### Z. 실수 복구·초보자 사용자 시험

- [ ] Z-01 빈 값·느린 응답·실행 실패·제한 초과·세션 만료가 있는 경우를 관찰한다. 입력을 불필요하게 잃지 않고 사용자가 이유와 재시도/다음 행동을 알 수 있다.
- [ ] Z-02 입문자에게 처음 입력→Lens 읽기→위치 확인→수정→결과 설명 과제를 맡긴다. 시간·힌트 사용·재시도·막힌 지점과 본인의 설명을 기록하고 합의한 성공 기준으로 평가한다.
- [ ] Z-03 대표 입력을 단순 복사한 뒤가 아니라 일부를 바꾼 새 입력의 결과를 예측하게 한다. 설명 이해 여부와 단순 정답 성공을 구분하고 학습 효과가 입증됐다는 과장은 하지 않는다.

## 공개 판단

- 적용되는 항목에 근거 있는 통과 기록이 있어야 한다. 해당 없음은 이유를 검토하고, 자문 대기·미실시는 통과로 계산하지 않는다.
- 공개 경계를 깨는 문제·무제한 실행·권한 우회·민감정보 노출 등은 조치·재검증 전 공개를 보류한다. 잔여 위험은 승인자·사유·범위·재검토 시점을 기록하며 해결 완료로 표현하지 않는다.
- 마지막에 같은 공개 후보의 기능·보안·브라우저 흐름을 함께 확인한다. 테스트 개수나 체크리스트 작성만으로 OWASP/WCAG 인증 또는 안전 보증을 주장하지 않는다.
- 이번 문서·댓글 등록으로 어떤 이슈도 자동 종료하지 않는다. 실제 검증과 결과 검토, 별도 공개 승인이 뒤따라야 한다.

## 출처와 활용 범위

- [OWASP Top 10:2025](https://owasp.org/Top10/2025/): I–T의 위험 분류 기준. 모든 항목이 현재 존재하는 취약점이라는 뜻은 아니다.
- [OWASP ASVS 5.0](https://asvs.owasp.org/): 자문 후 구체적인 검증 요구사항을 선택·대조할 기준. 이 문서는 ASVS 전체 충족표가 아니다.
- [OWASP API4:2023](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/): 요청 크기·횟수·실행시간·자원/비용 상한 검토에 활용.
- [OWASP DoS](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html), [세션 관리](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html): 계층별 남용 방지, 서버 측 만료와 유휴/최대 수명 구분.
- [MDN X-Forwarded-For](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For), [CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox): 신뢰 프록시와 직접 HTML 접근의 보안 경계.
- [WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/): 키보드·초점·대비·확대 등 사용자 편의성/접근성 점검에 활용. 전체 적합성 인증은 별도다.
