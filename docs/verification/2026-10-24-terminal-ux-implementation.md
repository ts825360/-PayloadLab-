# 터미널 UX 구현 검증 근거

연결: [#22](https://github.com/ts825360/-PayloadLab-/issues/22), [#13](https://github.com/ts825360/-PayloadLab-/issues/13). 진행 상태는 [WORK-STATE](../WORK-STATE.md)에서만 관리한다.

## UX-01 — 진단 어댑터

2026-10-24, 착수 기준 main `4392096`. frontend/src/terminal/diagnostics.js와 테스트를 추가했다. 기존 API·랩·화면은 변경하지 않았다.

- Red: 모듈 부재 확인 후 빈 함수에서 8개 중 대표 진단·유니코드 2개 실패, 폴백 6개 통과.
- Green: 실제 Permission denied 구절을 코드포인트 범위로 지정하고 기존 Lens의 why/next를 재사용했다. 신규 8개 모두 통과.
- 전체 Docker Vitest: **13개 파일, 62개 테스트 통과**.
- Docker Vite build: **종료 코드 0**, 478개 모듈. 새 어댑터는 아직 화면에 import하지 않아 기존 bundle에 연결되지 않았다.
- 브라우저 확인: 이 단계는 순수 함수이며 UI가 없어 해당 없음. 실제 밑줄·hover/Lens 연결이 완료됐다고 보고하지 않는다.

검증 명령:

```powershell
docker compose exec -T frontend npm test -- src/terminal/diagnostics.test.js --reporter=dot --maxWorkers=1 --minWorkers=1
docker compose exec -T frontend npm test -- --reporter=dot --maxWorkers=1 --minWorkers=1 --testTimeout=15000
docker compose exec -T frontend npm run build
```

시행착오: 기본 워커는 컨테이너 프로세스 제한에서 spawn EAGAIN이 발생했다. 워커를 제한해 해결했다. 전체 2개 워커 검사에서는 기존 13개 조합 UI 시험이 5초 제한을 초과해 61/62 통과였으며, **assertion을 변경하지 않고** 1CPU 환경에서 단일 워커·15초 예산으로 재실행해 62/62 통과했다. 해당 UI 시험의 실제 실행 시간은 재검사에서 2.7초였다. 위 설정은 검사 명령에만 적용했으며 앱·Docker 자원 제한·테스트 전역 설정은 바꾸지 않았다.

소스 자가 검토: 알려진 category/status와 실제 stderr 구절을 모두 확인한다. 원문은 수정하지 않고 미지원 trace에서 원인을 지어내지 않는다. 범위를 JS UTF-16 offset으로 소비하지 않도록 후속 렌더러도 코드포인트 slicing을 사용해야 한다.

## UX-02 — 원문 밑줄과 Lens 연결

2026-10-24, 착수 기준 `9ccf1bb`. DiagnosticText가 Permission denied의 정확한 구절만 표시한다. hover/키보드 초점은 짧은 설명, 선택은 현재 Lens에 초점 이동으로 연결한다. 입력 수정 후 지난 출력은 읽기 전용 요약만 제공해 새 입력의 Lens와 섞지 않는다. 원문 pre의 textContent와 줄바꿈을 유지하고 HTML로 실행하지 않는다.

- Red: 미구현 컴포넌트 import 실패, 연결 전 두 검사에서 표시 버튼 부재 확인. 추가 hover Esc 검사에서 툴팁과 관찰 닫힘 확인이 동시에 열리는 충돌도 확인했다.
- Green: 컴포넌트 7개, 실습 출력 3개, App 연결 5개 통과. 현재/과거 진단 분리와 Esc 우선 닫힘을 포함한다.
- 전체 프론트: **14개 파일, 71개 통과**. 위와 같은 단일 워커·15초 검사 명령을 사용했다.
- 빌드: **481개 모듈, 종료 코드 0**. 전체 검사 실행 중 병행한 첫 빌드는 `Aborted (core dumped)`였으나 검사 종료 후 단독 재실행은 통과했다. 자원 제한을 완화하거나 Docker 설정을 바꾸지 않았다. 이후 테스트와 빌드는 순차 실행한다.
- **브라우저 검증 대기:** 현재 Work 설정에서 로컬 브라우저 사용이 비활성화되어 도구가 거절했다. 실제 hover·클릭·테마 대비·복사·확대 배치는 확인하지 못했다. 자동 DOM 검사를 실제 브라우저 검증으로 보고하지 않는다.

백엔드·명령 실행·네트워크 기능은 변경하지 않았다. 권한 오류 한 가지의 연결이며 문법/미지원 진단, Linux 데스크톱 전체, 입력 편집면은 후속 작업이다.

## UX-03 — 전용 터미널 입력면

2026-10-24, 기준 `09142b0`. Linux 퀴즈·권한의 폼 입력을 TerminalInput으로 분리했다. 실제 입력은 네이티브 textarea 하나이며 기존 Enter/Shift+Enter/IME 처리와 2000자 제한을 재사용한다. 프롬프트는 입력 행에 한 번 표시한다. 한 줄에서 시작해 최대 144px까지 늘어나고 장식 면은 같은 글꼴·줄바꿈·스크롤 위치를 사용한다.

Permission denied의 파일 경로와 실제 `cat 경로`가 정확히 일치할 때만 같은 진단에 input 범위를 추가했다. 파일 경로의 밑줄은 권한 검사 대상을 뜻하며 명령 오타 판정이 아니다. 입력을 바꾸면 이전 밑줄·선택 단추는 사라진다. 분석 중에는 실행 오류를 만들지 않는다.

- Red: 입력 컴포넌트 미구현 import 실패, 어댑터 입력 범위와 실제 InputDock 전용 입력 통합 assertion 실패.
- 집중 검사: **31개 통과**, 이후 실제 App의 경로 밑줄·입력 변경 제거도 검사에 추가.
- 전체 프론트: **15개 파일, 79개 통과**. 기존 13개 랩의 안내·예정 상태·원문 출력·단축키 회귀를 포함한다.
- Vite build: **483개 모듈, 종료 코드 0**. 테스트 종료 후 순차 실행했다.
- **브라우저 미검증:** Work의 브라우저 제어 비활성화가 유지되어 기준선의 실제 픽셀 정렬·200% 확대·스크롤·IME 실제 키보드·선택/복사는 확인하지 못했다. DOM 이벤트 검사는 이 검증을 대신하지 않는다.

새 편집기 의존성·실제 명령 실행·서버 상태·브라우저 영구 학습 기록은 추가하지 않았다. CMDi의 전용 입력 연결과 전체 데스크톱 전환은 후속 단계다.

## UX-04 — 시도별 터미널 기록

2026-10-24, 기준 `f9300e5`. TerminalTranscript가 현재 랩의 기존 시도 목록을 순서대로 표시한다. 각 명령의 원문 stdout/stderr·종료 코드와 한국어 해설을 분리한다. 선택한 시도만 현재 Lens로 연결하며 과거 오류의 툴팁은 해당 시도의 설명을 유지한다.

관리자 전환 명령은 반환된 root 프롬프트가 아니라 simulation의 실행 전 identity를 사용한다. 미지원 명령도 화면 기록에는 남지만 백엔드 권한 history에서 제외하는 기존 계약은 유지했다. 새로운 저장소나 기록 API는 추가하지 않았다. 기록 자체의 스크롤만 이동하도록 구성했으며 전체 페이지 scrollIntoView는 사용하지 않는다.

- Red: 기록 컴포넌트 부재·App의 터미널 기록 영역 부재 확인.
- 집중 검사: **13개 통과**. 신규 기록 5개는 복수 시도 순서, 원문 줄바꿈/분리, 전환 전 사용자, 현재/과거 진단, 분석 제외, HTML 텍스트 처리를 검증한다.
- 전체 프론트: **16개 파일, 84개 통과**.
- Vite build: **485개 모듈, 종료 코드 0**. 검사 종료 후 순차 실행했다.
- 실제 로컬 HTTP: 프론트와 신규 모듈 응답 **200**. 브라우저 화면 렌더 검증은 아니다.
- 실제 로컬 모의 API: `cat /lab/report.txt` → permission_denied/student, `sudo /lab/maintenance` → elevated/student→root, 그 기록을 포함한 `cat /lab/report.txt` → command_ok/root/`training-report\n`를 확인했다. 이는 교육용 API 요청이며 호스트 셸/권한 변경이 아니다.
- **브라우저 미검증:** 스크롤 위치·긴 출력/확대·라이트/다크 가독성은 여전히 대기. UX-02/03과 같이 구현·자동 검사 완료와 최종 검증 완료를 구분한다.

이 단계의 검증으로 #22/#13 전체나 공개 전 보안 점검이 완료된 것은 아니다. 권한 TUI(UX-05), Linux 모드 전환/복귀(UX-06), CMDi/퀴즈 확장, 웹 배치/다크 디자인과 최종 교차 검증은 WORK-STATE의 후속 작업이다.
