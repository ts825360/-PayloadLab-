## 결과와 확인 범위

등록된13개 실습과 프론트 안내13개가 일치했다. 정의·성립 조건·난이도별 목표는 최초 안내 화면13개에서 코드와 대조했고, 총27개 단계는 실제 로컬 화면에서 실행→결과 관찰→관찰 확인→이해 질문→다음 단계/학습 마치기까지 진행했다. 1차 예시 경로에서는 오류를 찾지 못해 런타임 소스를 수정하지 않았다. 이후 대체 입력을 포함한 2차 검증에서 진행 판정1건과 조사 표현을 보완했다. 아래 별도 기록을 참조한다.

자동 비교: [실제 route 결과·전체 문안·27개 단계 JSON](2026-10-27-learning-flow-cases.json).

이 검증은 AI가 현재 안내 예시를 따라간 결과다. 사용자가 직접 이해했거나 팀이 최종 문안을 승인했다는 뜻이 아니다. 13개 실습의 모든 입력·상태·화면 크기·접근성·보안을 통합 검증했다는 뜻도 아니다. 검증 시점에는 로컬 변경이었고 PR·main 반영·이슈 체크/종료는 하지 않았다. 이후 사용자 승인에 따라 이 기록을 포함하는 커밋으로 같은 브랜치에 공유한다. 커밋과 원격 전송 결과는 Git 상태로 확인하며 최종 문안 승인과 구분한다.

## 정의·성립 조건과 실제 규칙

- SQL: 입력을 SQL 문자열에 합치는 문맥을 설명한다. Easy의 이름·고정된 틀린 비밀번호·AND와 실제 SQLite 결과를 대조했다. Normal은 정확한 대문자 OR 제거 뒤 문장 오류를 관찰하고 다른 표기의 조건으로 guest까지 반환됨을 확인했다.
- XSS: HTML 문맥과 실행 가능한 내용의 해석을 조건으로 설명한다. 일반 글자→표시 태그→script 규칙, Normal의 소문자 필터와 다른 표기를 대조했다. recognized·success=true는 교육용 태그 규칙 결과이며 이번에는 미리보기를 열거나 실제 스크립트 실행을 증명하지 않았다.
- IDOR: 객체번호와 소유권을 구분한다. Easy는 본인/타인 주문의 소유 관계를 대조했다. Normal에서 주문1043의 소유자는2001이고, claimed_user_id=1은 blocked로 완료 불가, 2001은 exposed로 진행 가능했다. 현재 사용자1042와 요청의 주장은 서로 다른 정보다.
- SSRF: 요청 주체와 목적지 검증을 설명한다. Easy 공개/루프백 더미 응답, Normal 신뢰 문자열과 파싱한 호스트의 차이를 관찰했다. DNS·HTTP 요청은 하지 않는다.
- CMDi: 입력과 셸 문법이 결합하는 경계를 설명한다. Easy의 일반 호스트/추가 명령, Normal의 세미콜론 차단과 다른 구분자를 비교했다. 실제 ping·셸 실행은 없다.
- Linux: 공격이 아닌 명령·옵션·경로 퀴즈로 설명한다. Easy의 목록, Normal의 권한·소유자를 더한 긴 목록을 대조했다. 퀴즈 답과 실제 Linux 문법 판정을 구분한다.
- 권한: 현재 사용자·파일 소유자·읽기 권한·허용 도우미를 연결한다. whoami→권한 목록→읽기 거부→sudo 규칙→가상 사용자 변화를 관찰했다. 실제 OS 권한 변경은 없다. Normal은 안내·실행 모두 구현 예정으로 유지된다.

## Easy/Normal와 진행 조건

27개 모든 단계에서 실행 근거를 얻어도 관찰 확인 전에는 다음 단계가 비활성화됐다. 마지막 질문이 있는 단계는 관찰 확인 후에도 정답 선택 전에는 완료할 수 없었고 정답 선택 뒤에만 마칠 수 있었다. 각 안내의 끝에서 ‘이 안내를 마쳤어요’를 확인했다.
Normal6개는 최초에 입력 예시가 숨겨져 있고 목표를 먼저 표시했다. ‘단서 보기’를 열면 수정 가능한 예시가 나타났고 직접 실행한 뒤 진행할 수 있었다. 예시 채우기를 실행이나 자동 통과로 취급하지 않는다.

직접 route 호출27개에 대해 각 단계 accept=true, 실행 전 분석 accept=false, 다른 유형의 trace accept=false를 Node에서 검사했다. 등록 목록13개 일치와 권한 Normal 안내 부재도 검사했다. 브라우저 조작과 별도인 자동 비교다.

화면 예: [처음 진입 시 정의·조건 안내](assets/2026-10-27-learning-flow-primer.png), [관찰과 이해 확인 뒤 안내 완료](assets/2026-10-27-learning-flow-complete.png). 캡처는 당시 보이는 화면이며 모든 해상도·확대에서의 가독성을 입증하지 않는다. 전체 텍스트는 위 JSON에 보존했다.

## 검사 중 구분한 사항

검증 자료에서 처음에는 주문번호1043을 소유자 번호로 잘못 넣어 Normal이 차단됐다. 실제 데이터의 owner_id=2001을 확인해 검증 입력을 고쳤다. 제품의 소유권 판정 오류가 아니었다.
기존 기록이 많은 터미널에서는 새 실행 뒤에도 보존되는 기록 수가 늘지 않을 수 있었다. 단순히 article 수 증가만 기다리던 검증 방식을 실행 버튼 복귀·최신 기록·학습 근거 확인으로 바꿨다. 앱의 기록 정책은 수정하지 않았다.

관련 프론트 학습 안내14개·통합 작업공간4개, 합계18개가 통과했다. 관련 프론트 회귀 결과는 [이번 실행 로그](evidence/2026-10-27-learning-flow-frontend-tests.txt)를 참조한다. 앞선 백엔드226개·프론트109개·빌드는 이전 단계 결과이며 이번에 전체를 재실행한 것으로 적지 않는다. 1차에는 제품 소스를 바꾸지 않아 관련 학습 안내·통합 작업공간 검사와 위 실제 경로 비교를 수행했다. 2차 수정 뒤 전체 검사 결과는 아래에 구분했다. 확인한 브라우저 경고·오류 로그는 없었다.

    python docs/verification/scripts/learning_flow_review.py

[Python 생성기](scripts/learning_flow_review.py)는 현재 lesson 예시와 실제 로컬 route trace를 생성하고 [Node 검사](scripts/learning_flow_review.mjs)는 실제 프론트 단계 accept를 대조한다. 브라우저 기록은 AI가 실제 UI를 조작해 별도로 수집했으며 생성기만으로 재생성되지 않는다.

## 2차 검증 — 2026-10-27

검사 대상을 안내 예시 외의 유효한 입력·무관한 입력·실행 전 분석·이전 단계 결과·오답으로 넓혔다. 이 검증 시점에는 미커밋·미push였고 이슈 체크/종료는 하지 않았다. 이후 사용자 승인으로 공유하는 상태는 위에 기록했다.

### 발견과 수정

1. 권한 Easy의 파일 소유자·권한 관찰 단계에서 ls -l /lab은 허용된 명령이고 report.txt의 mentor·-rw-------를 표시하지만, 안내의 정규식이 이 명령을 인정하지 않았다. 실제 화면에서 관찰 체크 뒤에도 다음 단계 비활성화, 새 회귀 검사1개 실패로 재현했다. lesson-catalog.js의 해당 단계만 /lab과 /lab/report.txt 양쪽을 허용하도록 수정했다. pwd·ls /lab·미지원 경로는 이 단계의 근거로 인정하지 않는다. 실제 허용 명령·권한 판정·실습 성공 기준은 바꾸지 않았다.
2. 실제 pwd 설명의 ‘폴더을’과 id의 ‘번호을’은 명령별 조사를 붙여 ‘폴더를·번호를’로 바로잡았다. 이 변경은 practice_extensions.py의 설명 문자열에만 해당한다.

[수정 전 결과·수정 후 실제 화면 대조](evidence/2026-10-27-learning-flow-second-browser.json). 화면에서 ls -l /lab의 기존 실행 근거가 수정 후 인정되고 다음 단계가 활성화됨을 확인했다. pwd로 새로 실행하면 여전히 진행 불가, 기존 ls -l /lab/report.txt는 관찰 확인 뒤 진행 가능했다. [기존 예시의 정상 진행 화면](assets/2026-10-27-learning-flow-second-review.png)은 제품 수정 뒤 촬영했다.

### 최종 검사

- 백엔드 전체 **226개 통과**. [새 실행 로그](evidence/2026-10-27-learning-flow-second-backend-tests.txt).
- 프론트 전체 **19파일110개 통과**. 새 회귀 검사1개는 수정 전 false/true 불일치로 실패한 뒤 통과했다. [새 실행 로그](evidence/2026-10-27-learning-flow-second-frontend-tests.txt).
- 빌드 **성공·488모듈**. [새 실행 로그](evidence/2026-10-27-learning-flow-second-build.txt).
- 등록13개·기존27단계 route/accept 비교 통과. 각 단계에 null trace·execution 없음·analysis 상태를 적용한 **81건**이 모두 진행 불가였다.
- 실제 route를 호출한 **18개 입력 대조** 통과: 12개 실습의 마지막 목표에 맞지 않는 입력, 권한 파일 단계의 대체 명령3개·무관하거나 미지원인 명령3개. 분석 응답은 모두 진행 불가. [실행 로그](evidence/2026-10-27-learning-flow-second-model-tests.txt), 전체 입력·실제 결과는 앞의 사례 JSON의 probes에 저장했다.
- 실제 화면에서 분석+관찰 체크만으로 진행 불가, 새 실행 뒤 관찰 체크 해제, 이전 단계 결과 재사용 불가, 입력 수정만으로 진행 불가를 확인했다. 마지막 질문의 오답은 완료 불가, 정답은 가능했고 권한 Normal의 실행 버튼은 없었다. 브라우저 경고·오류 로그는 없었다.

SQL Normal의 필터 단계는 필터가 입력을 바꿨다는 사실을 관찰하는 단계라 문법 오류 결과도 유효한 근거다. 모든 오류 상태를 무조건 탈락시킨다는 검증 가정을 적용하지 않고 실제 입력·해당 단계의 목표로 대조했다. 안내 관찰과 실습 성공의 구분을 유지한다.

최종 남은 범위는 위 ‘남은 일’과 같다. 본인·팀 최종 검토, 터미널 hover·터치·확대, CSV 범위는 이번 2차 검증으로 완료 처리하지 않는다.
