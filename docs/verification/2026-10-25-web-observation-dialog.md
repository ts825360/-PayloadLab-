# 웹 입력·Lens와 결과 창 검증

검증일: 2026-10-25. 수정 기준: main `11c1a40`. 관련: #13, #22.

## 바뀐 동작

- 웹 기본 화면은 **넓은 목차 | 입력창과 Lens**다. 데스크톱 목차는 260px, 중간 폭은 240px이며 이름을 숨기지 않는다.
- 처리 흐름·결과는 상시 패널 대신 dialog로 연다. Enter 실행과 Lens의 위치 보기·시도 기록에서 접근한다. 자동 입력 분석만으로는 열리지 않는다.
- Esc → 닫기 확인 → Enter로 닫는다. X는 확인 없이 바로 닫는다. 닫힌 창은 DOM에서 제거되어 빈 공간을 차지하지 않는다.
- 입력과 시도 기록·학습 진행을 보존한다. 닫으면 실행에 사용한 입력이나 Lens의 원래 버튼으로 초점을 돌린다. 기존 시도 선택·두 시도 비교를 유지한다.
- 시작 전 정의·성립 조건·학습 목표는 Lens의 학습 안내에서 읽는다. 별도 상시 관찰 패널을 만들지 않는다.
- LinuxDesktop·터미널 CSS·백엔드·데이터셋은 수정하지 않았다. 실제 네트워크나 셸 실행은 추가하지 않았다.

## 자동 검사

```text
docker compose exec -T -e DEBUG_PRINT_LIMIT=500 frontend npm test -- --reporter=dot --maxWorkers=1 --minWorkers=1 --testTimeout=15000
Test Files 19 passed (19)
Tests 100 passed (100)
exit 0

docker compose exec -T frontend npm run build
Vite 5.4.21, 489 modules transformed, exit 0
```

신규 웹 검사 4개: 기본/분석 중 창 없음, Enter와 Esc 확인 닫힘, X와 기록 재열기, 실행 응답 전 초점 유실 시 복원. 기존 학습·통합 검사는 새 열기/닫기 흐름에 맞춰 갱신했고, 입력 단축키·13개 랩의 시작 학습·기록 비교·Linux 화면 회귀 검사를 유지했다.

실제 브라우저에서 닫은 뒤 초점이 body로 옮겨지는 문제를 발견했다. inert 적용 후 effect에서 초점을 저장하면 원래 입력을 잃을 수 있었다. 응답 지연 중 초점 유실 검사를 먼저 실패시킨 뒤, 실행·열기 이벤트에서 출발 요소를 저장하도록 수정했다. 같은 검사와 실제 브라우저의 `payload-input` 초점 복원이 모두 통과했다.

## 남은 범위

이번 검증은 웹 배치·결과 열기/닫기·초점 복원에 한정된다. UX-10의 다크 디자인 재설계, UX-11의 실제 사용자·스크린리더·200% 확대 검사, 다른 유형 전체의 실제 브라우저 시나리오와 공개 전 보안 점검 완료를 의미하지 않는다. #13/#22는 남은 범위 때문에 열어둔다. 공개 배포는 하지 않았다.

최신 실행 순서는 [WORK-STATE](../WORK-STATE.md)가 관리한다.
